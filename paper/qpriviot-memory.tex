\abstract{LLM agents accumulate per-user memory (distilled notes and
preferences) that makes them personal and effective. Pooling it across users
would give a fleet a shared \textbf{routing prior} over what the fleet
collectively knows, but memory is exactly the sensitive artifact: published
extraction and membership-inference attacks recover verbatim user facts from it.

We aggregate per-user memory-note embeddings into a bucketed \textbf{centroid
memory} under \textbf{Secure Aggregation} composed with the discrete
\textbf{Skellam mechanism}, so the pool carries a central differential-privacy
guarantee with no trusted curator and no note in the clear. We evaluate on real
long-horizon conversational memory and on LLM-distilled agent notes, insisting
that utility and leakage be read at the same operating point.

Four findings. First, on a \textbf{joint frontier} measuring both axes at every
bucket fidelity, the coarse regime is usable and safe at once: the pool keeps
\textbf{95\% of clean retrieval utility} while a calibrated likelihood-ratio
attack falls from an AUC of 0.833 to the 1\% false-positive floor. Second, that
endpoint is \textbf{invisible to the weak attack the literature defaults to}: an
uncalibrated cosine proxy reports chance on the very release the calibrated
attack breaks, so a proxy-only evaluation would certify a leaking pool as safe.
Third, \textbf{data-dependent preprocessing silently inflates such results}:
fitting the projection on user notes is an unaccounted release that also
manufactures an apparent dimension effect, which vanishes under a public-seed
projection. Fourth, we account for the \textbf{repeated release} a deployed
memory requires, whose cost grows only as the square root of the round count.
Every parameter of the mechanism is public or DP-accounted, so the reported
budget covers the whole pipeline.}

\keywords{Differential privacy, Secure aggregation, Skellam mechanism,
LLM agent memory, Federated learning, Membership inference}

\section{Introduction}\label{sec:intro}
%%=====================================================================%%

\paragraph{Agent memory is the new sensitive payload.}
Production LLM-agent frameworks such as A-MEM~\cite{xu2024amem} and
Mem0~\cite{chhikara2024mem0} persist a per-user store of distilled notes:
``the user is allergic to penicillin,'' ``prefers metric units,'' ``is migrating
a Postgres 14 cluster.'' This memory is what makes an agent personal, and it is
also a dense concentrate of personally identifying information. A natural,
high-value idea is to \textbf{share memory across users}, so that a fleet of
agents can profit from what the fleet collectively knows. But na\"ively pooling
raw notes is a privacy disaster, and recent work shows the threat is concrete
rather than hypothetical: \textbf{MEXTRA}~\cite{wang2025mextra} extracts verbatim
memory content, and \textbf{MRMMIA}~\cite{chen2026mrmmia} performs membership
inference against agent memory with high success.

\paragraph{What the pool is: a routing prior, not a note exchange.}
The shared pool is $K$ \emph{centroid vectors} and \textbf{no text}. A receiving
agent cannot read another user's note out of it: verbatim knowledge transfer
across users is \emph{not} what this mechanism delivers, and any mechanism that
did deliver it would be releasing the very artifact the attacks of
\secref{sec:related} consume. What the pool \emph{does} deliver is a
\textbf{shared routing prior}: a fleet-level map of \emph{which regions of memory
space hold knowledge}, against which any agent can route a query (to the right
local memory, the right tool, the right public corpus) without any note leaving
its device. This is what our metric measures (evidence-recall: did the query
reach the bucket containing its evidence?), and \secref{sec:frontier} shows the
coarse pool is released nearly for free.

\paragraph{Why the obvious defenses are insufficient.}
Access-control layers (\emph{Collaborative Memory}~\cite{rezazadeh2025collabmem})
and on-device masking (\emph{MemPrivacy}~\cite{chen2026memprivacy}) restrict
\emph{who} sees a note but provide no formal guarantee over the \emph{aggregate},
and a curated central datastore~\cite{abouelenein2026dpdatastore} reintroduces a
trusted party. What is missing is a mechanism that (a) needs \textbf{no trusted
curator}, (b) gives a \textbf{central-DP guarantee over the shared pool}, and
(c) is shown to actually \textbf{degrade the known attacks} while keeping the
pool useful.

\paragraph{Our approach.}
We treat federated memory aggregation as a \textbf{secure summation of per-user
bucketed embeddings}. Each user projects their notes to a working dimension $d$
with a \textbf{public-seed random projection}, maps them into $K$ shared buckets
(random-hyperplane LSH), forms a per-bucket sum-vector, and contributes it
through \textbf{SecAgg}~\cite{bonawitz2017secagg} so the server sees only the
masked sum; the \textbf{Skellam mechanism}~\cite{agarwal2021skellam} adds
calibrated discrete noise that \textbf{composes under summation}, yielding a
single distributed-DP guarantee on the pooled centroid memory. Retrieval is
cosine lookup against the noised centroids. The cryptographic path is used
\textbf{verbatim} from federated discrete-DP work; the novelty is the
\emph{payload} (agent-memory embeddings) and the \emph{evaluation} (a measured
attack-success drop).

\paragraph{Why this payload, and why now.}
Federated DP for LLM \emph{adaptation} (DP-LoRA, prompt tuning) is saturated,
and recent federated-privacy work for LLMs targets \emph{other} objects: DP
synthetic-data generation (POPri~\cite{hou2025popri}) and privacy-constrained
agent self-evolution (Fed-SE~\cite{chen2025fedse}), rather than the
aggregation of a shared \textbf{memory} pool; contemporaneous agent-memory
security surveys~\cite{lin2026survey} catalogue attacks and
access-control/redaction defenses but no curator-free DP aggregation mechanism.
The nearest mechanism, \emph{DP Datastore
Generation}~\cite{abouelenein2026dpdatastore}, privatises a retrieval datastore
but in a \textbf{centralized, single-curator} setting with generic additive noise
and no secure aggregation (\secref{sec:related}). Federated agent-\emph{memory}
aggregation under SecAgg $+$ discrete Skellam DP is thus an open seam. Crucially,
agent-memory objects are \textbf{genuinely tiny-dimensional and often already
discrete}, which is exactly the regime where the discrete Skellam mechanism is
most efficient and where our dimension analysis is most credible.

\subsection*{Contributions}

\begin{enumerate}
  \item \textbf{A federated agent-memory aggregation mechanism} that composes
    SecAgg with the Skellam mechanism over bucketed memory-note embeddings,
    giving a curator-free central-DP shared routing prior
    (\secref{sec:centroid}--\secref{sec:release}).

  \item \textbf{A joint utility/leakage frontier, and a positive endpoint on it.}
    We measure both axes \textbf{at every fidelity $K$}, which is what a two-axis
    claim requires. On the frontier the coarse-$K$ regime is
    usable \emph{and} membership-safe at one operating point: at $K = 32$ the pool
    retains \textbf{95\% of clean evidence-recall} at $\eps \approx 9.3$ while a
    calibrated offline-LiRA attack falls from \textbf{AUC 0.833 / TPR@1\%FPR 0.175}
    to the \textbf{1\% false-positive floor} (0.011), and it does so at
    \emph{every} fidelity we measured, so the membership axis is flat in $K$ and
    $K$ is chosen on utility alone (\secref{sec:frontier}).

  \item \textbf{Closed-set reconstruction is not defeated, and cannot be.}
    Decode-extraction falls only $0.771 \to 0.396$ at $K = 32$, against a
    \textbf{measured} chance floor of $0.010$, i.e.\ $38\times$ above it. The metric is
    the wrong instrument: it tracks retrieval retention exactly across the sweep,
    because a centroid that retrieves \emph{must} point at its own bucket, and a
    closed-set ``hit'' certifies only that a note the adversary already holds falls in
    a bucket that the \textbf{public} anchors let anyone compute without the release.
    It is an upper bound on inversion, informative only when low. \textbf{Open-set
    inversion remains untested and is this paper's chief gap}
    (\secref{sec:decode-floor}).

  \item \textbf{A methodological result: the weak attack the literature defaults
    to is blind exactly where it matters.} The uncalibrated cosine proxy used by
    prior agent-memory work reads \textbf{0.504 (chance) at $K = 32$}, on the
    same clean release the calibrated attack breaks at AUC 0.833. A proxy-only
    evaluation therefore certifies a leaking pool as safe, and reports that leakage
    exists only in a sparse regime nobody would deploy (\secref{sec:proxy-blind}).

  \item \textbf{The dimension ``crossover'' is an artifact of data-dependent
    preprocessing.} Fitting the projection on user notes is an unaccounted release
    \emph{and} it fabricates the finding that tiny-$d$ is jointly optimal for privacy
    and utility. Under a data-independent projection the effect \textbf{vanishes on
    both axes}: no ordering among $d$ survives the seed noise on the utility axis, and
    the pre-DP leakage gradient flattens, with an identity-projection control
    ($d = 384$) that all three projections must and do agree on
    (\secref{sec:crossover}). The confound is not specific to this paper.

  \item \textbf{An end-to-end-accounted mechanism, including repeated release}:
    the projection, the LSH anchors, the clip bound $C$ and the quantiser bound
    $B := C$ are all public or DP-selected, so the reported $\eps$ covers the
    entire pipeline rather than only its last stage (\secref{sec:clip},
    \secref{sec:accounting-results}); the clip-selection cost is 0.2\% of the
    budget. Because agent memory is \emph{re-aggregated} as users write notes, we
    also account for the $T$-round release that a deployment actually performs:
    naive re-release is ruinous ($\eps\ 9.3 \to 93$ for a month of daily rounds),
    but the cost is $\sqrt{T}$ in the noise scale, so a \textbf{monthly cadence
    sustained for a year fits inside the same $\eps \approx 9.3$ at 81\%
    retention} (\secref{sec:multiround}).

  \item \textbf{A rigorous, tightened accounting}: an exact Skellam-RDP $\eps$ for
    the discrete mechanism (Agarwal et al.\ Thm.~3.5~\cite{agarwal2021skellam}), a
    proof that \textbf{discretisation is free} at our resolution, and a
    \textbf{vector-only release} that gives identical retrieval at
    ${\sim}1.5\times$ tighter $\eps$ because the count magnitude cancels under
    normalisation. The count channel's one non-redundant use is \emph{occupancy},
    and we show it \textbf{cannot pay for itself}: no occupancy rule is
    simultaneously free and accurate, because occupancy and membership are the same
    signal (\secref{sec:vector-only}, \secref{sec:occupancy}).

  \item \textbf{A realistic-payload validation, on the calibrated attack}: we run
    the LiRA \emph{directly on} LLM-distilled A-MEM/Mem0-style notes (the object
    a production agent actually stores), and the endpoint holds at the same
    operating point and the same budget as on raw turns (clean AUC $0.838$,
    TPR@1\%FPR $0.171$; both at the floor under DP). The uncalibrated proxy suggests
    distilled notes leak \emph{more} than raw turns; calibration shows they do not
    (\secref{sec:distilled}).
\end{enumerate}

Utility and proxy-leakage results are \textbf{5-seed means with final (not peak) metrics},
reported with their standard deviation; the calibrated-LiRA and live-agent results are
\textbf{3-seed} (each LiRA point aggregates 48 shadow releases, so its own sampling error is
small, but we flag the seed count rather than let the reader assume five). The harness and
grid are released (\secref{sec:repro}).

\section{Related Work}\label{sec:related}
%%=====================================================================%%

\paragraph{Federated DP with secure aggregation and discrete noise.}
Federated learning~\cite{mcmahan2017fedavg} trains on decentralised data without
centralising it, and SecAgg~\cite{bonawitz2017secagg} lets a server compute a sum
of client vectors without seeing any summand. To obtain a DP guarantee that
composes under that sum without a trusted curator, discrete mechanisms are used:
the \textbf{distributed discrete Gaussian}~\cite{kairouz2021ddgauss} and the
\textbf{Skellam mechanism}~\cite{agarwal2021skellam}, the latter being closed
under addition (the sum of Skellams is Skellam) and efficient at low bit-width.
Prior deployments target \textbf{gradient} payloads for model
training~\cite{abadi2016dpsgd}. We reuse this path \emph{verbatim} but change the
payload to \textbf{agent-memory embeddings} and the objective to
\textbf{retrieval}, not learning.

\paragraph{Privacy of LLM-agent memory.}
Agent frameworks A-MEM~\cite{xu2024amem} and Mem0~\cite{chhikara2024mem0} persist
distilled per-user memories. Their privacy is under active attack:
\textbf{MEXTRA}~\cite{wang2025mextra} extracts memory content and
\textbf{MRMMIA}~\cite{chen2026mrmmia} runs membership inference; a
memory-security survey~\cite{lin2026survey} catalogues this attack literature.
Defenses so far are \textbf{access control} (\emph{Collaborative
Memory}~\cite{rezazadeh2025collabmem}, which also introduces a
shared-vs-private memory split but governs \emph{who reads} a note, not the
aggregate) and \textbf{on-device masking / redaction}
(\emph{MemPrivacy}~\cite{chen2026memprivacy}); neither gives an aggregate formal
guarantee. We therefore \textbf{cite and reuse the attacks as our evaluation
harness} rather than claiming them, and provide the missing mechanism-side
guarantee.

\paragraph{Federated retrieval / datastores (the nearest prior art).}
\emph{DP Datastore Generation}~\cite{abouelenein2026dpdatastore} is the closest
existing mechanism: it partitions data with \textbf{locality-sensitive hashing}
and adds \textbf{calibrated DP noise to each bucket's aggregate}, releasing a
private datastore on which membership-inference accuracy falls to near-chance
($\approx 53.6\%$ at $\eps = 5$), the same LSH-bucket-plus-DP skeleton and
privacy-endpoint framing we adopt. It is, however, \textbf{centralized and
single-curator}, uses \textbf{generic additive (continuous) noise with no secure
aggregation}, and its payload is a \textbf{classification/retrieval datastore},
not cross-user agent memory. Our delta is therefore fourfold: (i) a
\textbf{federated, curator-free} release under \textbf{SecAgg}, where the noise is
added distributively and no party ever sees a summand; (ii) the \textbf{Skellam}
mechanism, whose \textbf{closure under summation} is precisely what makes the
distributed release \emph{equal} the intended central mechanism (a
discrete-Gaussian/continuous-noise datastore does not compose this way under
modular SecAgg); (iii) the \textbf{agent-memory embedding} payload and
cosine-retrieval objective; and (iv) the coupled \textbf{dimension/density
crossover} and the distilled-payload finding (\secref{sec:crossover},
\secref{sec:distilled}). \textbf{POPri}~\cite{hou2025popri} is federated and
private but produces \textbf{DP synthetic data via preference optimisation}, not
an aggregated memory/preference pool, so it is orthogonal;
\textbf{Fed-SE}~\cite{chen2025fedse} federates agent \emph{self-evolution} under
privacy constraints, adapting behaviour, not releasing a shared memory. To our
knowledge no prior work aggregates cross-user agent memory under SecAgg $+$
discrete-DP with a measured attack-drop endpoint.

\paragraph{Dimension dependence of DP.}
That utility degrades with dimension under DP is
classical~\cite{bassily2014erm} and was sharpened for deep models by Chen et
al.~\cite{chen2022price}. We do \textbf{not} claim the dimension dependence
itself. \secref{sec:crossover} instead shows that the apparent \emph{coupled}
crossover, in which dimension governs pre-DP \emph{leakage} and DP
\emph{utility-retention} simultaneously and so makes tiny-$d$ a joint optimum, is
an artifact of a data-dependent projection.

\section{Threat Model and Problem Setup}\label{sec:threat}
%%=====================================================================%%

\paragraph{Parties.} $N$ users, each with a local agent holding a set of memory
notes; an honest-but-curious aggregation server; and downstream agents that query
the shared memory.

\paragraph{Goal.} Produce a single \textbf{shared memory pool} (a set of $K$
centroid embeddings) that any agent can query by cosine similarity to retrieve
relevant knowledge contributed by the fleet, such that the pool carries a
\textbf{central $(\eps, \delta)$-DP guarantee at user granularity} and no
individual user's notes can be reconstructed or their membership inferred.

\paragraph{Trust / adversary.} No trusted curator: under SecAgg the server
observes only the masked sum, so the DP noise need not be added by a trusted
party. The adversary is a recipient of the released pool (the server, or any
downstream agent). It mounts:
\begin{itemize}
  \item \textbf{Membership inference} (MRMMIA analog): given a candidate note
    embedding $x$, decide whether the user who owns $x$ contributed to the pool.
    Score $s(x) = \cos(x, \mu[\mathrm{bucket}(x)])$; members pulled their own
    centroid and score higher. Metric: ROC-AUC ($0.5 =$ no leakage).
  \item \textbf{Extraction} (MEXTRA analog): advantage in reconstructing an
    in-bucket member embedding from the centroid; we report the
    member/non-member \textbf{extraction gap}.
\end{itemize}

\paragraph{The vulnerable subpopulation is a lens, not a bound.} In a \emph{sum} mechanism
leakage might be expected to concentrate where \textbf{few users contribute to a bucket},
since averaging ought to protect well-populated buckets. We therefore additionally
\emph{stratify} the similarity-proxy metrics by the \textbf{low-count tail} (buckets with
$\leq 3$ contributors), the intuitive worst case and the group agent-memory privacy most
obviously cares about (rare/unique notes).

That expectation holds \textbf{only against a weak adversary}. Averaging dilutes a member's
contribution relative to a \emph{population} baseline, which is all an uncalibrated cosine score
can measure; it does not remove the member's influence on the centroid, which is what a
\emph{per-target} likelihood ratio measures. Our headline attack (the calibrated LiRA of
\secref{sec:lira}) is accordingly scored \textbf{over all buckets, not the tail}, and it
re-identifies members of \emph{dense} coarse-$K$ buckets that the proxy reports as being at
chance (\secref{sec:frontier}, \secref{sec:proxy-blind}). The tail stratification is a property
of our \emph{evaluation lens}, retained for continuity with the published attacks; it is not a
claim about where leakage lives, and not a bound on where we looked.

\paragraph{Threat boundary (what we do not defend).} Our adversary is
\textbf{passive}: a recipient of the released pool (the honest-but-curious
server, or any downstream agent) and, under SecAgg, an observer of masked
traffic. Two adversaries are explicitly out of scope. (i) \textbf{Active,
colluding clients.} A malicious participant can inject structured notes to steer
particular bucket centroids across epochs, and query the pool before and after a
target user joins, turning the offline LiRA of \secref{sec:lira} into an
\emph{adaptive online} attack against specific delta vectors. Robust aggregation
against poisoning of a private vector-retrieval pool is an open problem,
orthogonal to the release mechanism analysed here. (ii) \textbf{Participation
metadata.} SecAgg hides a client's \emph{contents}, not the fact that it
participated; \secref{sec:release} specifies mandatory participation with padded
dummy payloads to close that channel, an assumption we state but do not measure.

\paragraph{Utility.} For a query $q$, retrieval routes to the top-$k$ centroids by
cosine; utility is whether the \emph{right} content is retrieved
(evidence-recall / answer-recall on real benchmarks, topic-accuracy on synthetic
corpora).

%%=====================================================================%%
\section{Bucketed Centroid Memory}\label{sec:centroid}
%%=====================================================================%%

Let each note $i$ of user $u$ have embedding $e_i \in \R^{D}$ from a sentence
encoder. We reduce to a working dimension $d$ with a \textbf{public-seed Gaussian
random projection} $P \in \R^{D \times d}$, $P_{jk} \sim \mathcal{N}(0, 1/d)$,
L2-normalize, and assign to one of $K$ buckets by random-hyperplane LSH: fix $K$
random anchors $a_1, \dots, a_K$ and set
$\mathrm{bucket}(i) = \arg\max_k \langle e_i, a_k \rangle$. Both $P$ and the
anchors are drawn from a \textbf{published seed and never touch user data}, so
shipping them to clients releases nothing and the $\eps$ of
\secref{sec:accounting} accounts for the \emph{entire} pipeline. A PCA fit on the
users' notes, the obvious alternative, is a data-dependent release whose privacy
cost is unaccounted, and \secref{sec:crossover} shows it also manufactures a
spurious finding.

Each user forms, per bucket $k$, a \textbf{sum-vector}
$v_u[k] = \sum_{i : \mathrm{bucket}(i) = k} e_i$ and a \textbf{count} $c_u[k]$.
The (non-private) shared centroid is

\begin{equation}\label{eq:centroid}
  \mu[k] \;=\; \mathrm{normalize}\!\left(
    \frac{\sum_u v_u[k]}{\sum_u c_u[k]}
  \right).
\end{equation}

Retrieval for query $q$ returns the top-$k$ buckets by $\cos(q, \mu[k])$. $K$
controls memory \emph{fidelity} (more buckets $=$ finer memory), $d$ controls
embedding \emph{resolution}; both, as we show, trade off against privacy.

%%=====================================================================%%
\section{Private Release: SecAgg + Skellam}\label{sec:release}
%%=====================================================================%%

\subsection{Clipping, quantisation, and sensitivity}\label{sec:clipping}

\paragraph{Per-user clipping and quantisation.} A user's contribution to the
release is not one bucket but the \emph{whole} payload: the concatenation
$V_u = [v_u[1]; \dots; v_u[K]] \in \R^{K \cdot d}$. We therefore clip $V_u$
\textbf{globally}, to a single L2 bound $C$, and only then quantise to integers on
a fixed grid of resolution $s = \texttt{range\_max} / B$
($\texttt{range\_max} = 10^{6}$, $B$ the quantiser bound). This yields integer
vectors amenable to SecAgg and to a discrete noise mechanism, with
\textbf{user-level L2 sensitivity exactly $\Delta_2 = C \cdot s$}.

\paragraph{Neighbouring relation.} Throughout, two datasets are neighbours if one
is obtained from the other by \textbf{adding or removing a single user}
(unbounded DP). This is what makes $\Delta_2 = C s$ exact: deleting a user removes
one clipped payload of norm $\leq C$. (Under the \emph{replace-one} convention the
same mechanism would have $\Delta_2 = 2 C s$, and every $\eps$ below would double.)
We use the same relation for the clip-selection mechanism of \secref{sec:clip}, so
the two costs compose against a single definition.

\subsection{The clip bound is a mechanism parameter, so it must be public
too}\label{sec:clip}

$C$ and $B$ are shipped to every client. The natural choice ($C =$ the 95th
percentile of the observed payload norms, $B =$ the largest observed coordinate)
is a \textbf{function of the private corpus}, so releasing it is an unaccounted
release, exactly the error \secref{sec:crossover} diagnoses for the projection.
Neither is expensive to fix.

\begin{itemize}
  \item \textbf{$B := C$ is free.} Since every note is L2-unit and the payload is
    clipped first, $|V_u[j]| \leq \norm{V_u}_2 \leq C$ for every coordinate $j$. So
    $B := C$ is a \emph{public} bound that provably never clips a coordinate, and the
    leading RDP term is invariant to it anyway: $\Delta_2 / \sqrt{\mu} = 1/\sigma$
    regardless of $s = \texttt{range\_max}/B$ (\secref{sec:accounting}). Nothing is paid.

  \item \textbf{$C$ is DP-selected.} We choose $C$ from a public geometric grid
    with the \textbf{exponential mechanism} on the rank utility
    $u(c) = -\left| \#\{u : \norm{V_u}_2 \leq c\} - q N \right|$, $q = 0.95$,
    sampling $c$ with probability $\propto \exp(\eps_c \, u(c) / 2)$. Its
    sensitivity under \textbf{add/remove} deserves care, because the count
    \emph{and} the target $qN$ both move when a user leaves. Removing a user whose
    norm is $\leq c$ drops the count by 1 and the target by $q$, so the argument of
    $|\cdot|$ shifts by only $1 - q = 0.05$; removing a user whose norm is $> c$
    leaves the count alone and shifts the target by $q$. Hence
    \begin{equation}\label{eq:clip-sens}
      \Delta u \;=\; \max(1 - q,\; q) \;=\; q \;=\; 0.95 \;\leq\; 1,
    \end{equation}
    and the sampler above, which would be $\eps_c$-DP at $\Delta u = 1$, is in
    fact $(q\,\eps_c)$-DP. We \textbf{charge the full $\eps_c$}, a 5\% conservative
    margin. It composes with the release in RDP via pure-DP $\to$ zCDP: an
    $\eps_c$-DP mechanism is $(\eps_c^2/2)$-zCDP, hence
    $\mathrm{RDP}_\alpha \leq \alpha \eps_c^2 / 2$~\cite{bun2016zcdp}. (Had we
    instead assumed the replace-one convention here while using $\Delta_2 = C s$ for
    the release, the two mechanisms would have been accounted against different
    neighbouring relations, a subtle way to under-count.)
\end{itemize}

We spend $\eps_c = 0.1$, which costs \textbf{0.2\% of the budget}
($\eps\ 9.29 \to 9.31$ at $\sigma = 0.6056$; \secref{sec:accounting-results}). The
grid is deliberately \textbf{coarse} (16 points spanning $[2, 64]$, a public range:
a user with $n_u$ unit-norm notes has $\norm{V_u}_2 \in [\sqrt{n_u},\, n_u]$, and
agent memories hold tens of notes per user), because the exponential mechanism's
rank error grows like $\log|\mathrm{grid}| / \eps_c$~\cite{smith2011quantile}.

\paragraph{The selection is conservative, and one-sidedly so.} The rank utility
saturates at $-0.05 N$ for \emph{any} $c$ above the largest observed norm, so at
small $\eps_c$ the entire upper tail of the grid stays competitive and $C$ is
biased \textbf{upward}: on LongMemEval-oracle at $K = 32$ it lands at
$21.7 \pm 8.5$ against a true p95 of $13.7 \pm 1.3$ (mean ratio $1.6\times$). That
error only ever \emph{adds} noise (it can never under-noise the release), so the
guarantee is safe, and the price is utility: evidence-recall@5 at $\eps \approx 9.3$
falls from $0.416$ (leaky empirical p95) to $\mathbf{0.406}$ at $K = 32$, and from
$0.117$ to $0.100$ at $K = 256$, where the signal-to-noise is thinner. We regard a
2\% headline utility cost as the correct price for an accounted guarantee, and note
the knob: $\eps_c = 0.25$ tightens $C$ to $13.4 \pm 1.3$ and recovers most of the
loss, at a total $\eps$ of $9.42$ instead of $9.31$.

\begin{remark}[Cross-bucket sensitivity: why the clip must be global]
\label{rem:global-clip}
Clipping each bucket-vector \emph{separately} to $C$ would \textbf{not} yield
sensitivity $C$. A user with notes in $b_u$ distinct buckets would contribute up
to $C$ in each, so the payload sensitivity would be
$\sqrt{\sum_k \norm{v_u[k]}^2} \leq \sqrt{b_u} \cdot C$, and an accountant still
charging $\Delta_2 = C s$ would under-count by $\sqrt{b_u}$. The blow-up is
governed by $b_u \leq \min(n_u, K)$, the number of buckets the user \emph{touches}
and \textbf{not by $K$ alone}: a user with $n_u$ notes cannot occupy more than
$n_u$ buckets. On LongMemEval-oracle (mean 21.9 notes/user, max 72) the busiest
user touches $b_{\max} = 21$ buckets at $K = 32$ and $54$ at $K = 1024$, so
per-bucket clipping would have inflated the true budget from the reported
$\eps \approx 9.31$ to $\eps \approx 69$ ($K = 32$) and $\eps \approx 159$
($K = 1024$), a broken guarantee. Our implementation clips globally
(\texttt{clip\_rows\_to\_norm(V\_u.reshape(1,-1), C)} in
\texttt{scripts/agentmem/\_agentmem\_leakage.py}), so every $\eps$ reported in this
paper is sound; line~\ref{alg:global-clip} of Algorithm~\ref{alg:main} makes this
explicit.
\end{remark}

\paragraph{Skellam noise, composed under the sum.} Each user adds Skellam noise
(a difference of two Poissons, per-coordinate variance $\mu = (\sigma C s)^2$) to
their quantised vector and submits it through \textbf{SecAgg}, so the server
recovers only $\sum_u (\mathrm{quantise}(\mathrm{clip}(v_u)) + \mathrm{Skellam})$.
Because the sum of independent Skellams is Skellam, the \emph{released sum} carries
the target noise with \textbf{no trusted curator}. Dequantising and dividing by the
(also-released or cancelled, \secref{sec:vector-only}) count gives the private
centroid $\tilde\mu$.

\paragraph{Implementation constraints of the integer path.} Three details the
accountant assumes and an implementation must honour.

\begin{itemize}
  \item \emph{Modular field size.} SecAgg sums in a finite field $\Z_p$; too small
    a $p$ and the integer sum wraps, silently corrupting the aggregate. Per
    coordinate the signal is bounded by $N \cdot \texttt{range\_max}$ and the
    aggregate noise has standard deviation $\sigma C s$, so it suffices that
    $p > 2\,(N \cdot \texttt{range\_max} + \kappa\,\sigma C s)$ for a tail factor
    $\kappa$ (we use $\kappa = 6$). At our operating point ($N = 500$,
    $\texttt{range\_max} = 10^{6}$, $\sigma C s = 6.06 \times 10^{5}$) this is
    $p > 10^{9}$. The reference implementation aggregates in \texttt{int64},
    exceeding the bound by nine orders of magnitude; the measured peak coordinate of
    the noised aggregate is $1.8 \times 10^{7}$. (The $\sqrt{d}$ that one might
    expect here does not appear: the constraint is per-coordinate.)

  \item \emph{Mandatory participation and padding.} A client with no new notes must
    still submit. It forms the all-zero payload, adds its Skellam share
    (line~\ref{alg:noise}) and its SecAgg mask, and submits a vector of identical
    shape. Because the noise is injected \emph{before} masking, an idle client's
    submission is distributionally indistinguishable from an active one's, so
    neither the server nor a network observer learns who used their agent this
    epoch. Uniform payload shape likewise prevents inferring that a user's memory is
    narrow (few occupied buckets) from the ciphertext.

  \item \emph{Rounding, and what clipping does to heavy users.} $\mathrm{round}(v s)$
    can lift the integer norm above $C s$ by at most $\sqrt{K d}/2$: at our operating
    point 16 against $\Delta_2 = 10^{6}$, a $1.6 \times 10^{-5}$ relative inflation,
    which we absorb rather than adopt the conditional randomised rounding
    of~\cite{kairouz2021ddgauss}. Note also that the clip of
    line~\ref{alg:global-clip} is a \textbf{scalar rescale}: it shrinks a heavy
    user's magnitude but leaves the direction of $V_u$ exactly unchanged, so a
    high-activity user's semantics are \emph{down-weighted, never distorted}. A
    deployment that wishes to bound that down-weighting can cap notes-per-user before
    aggregation, which lowers $C$ and hence the absolute noise.
\end{itemize}

\subsection{Vector-only release, and what the count channel is (and is not)
for}\label{sec:vector-only}

The natural design releases \textbf{two} channels (the sum-vector and the counts),
costing two RDP compositions. For the \emph{direction} of the retrieval centroid the
count is redundant: dividing by the scalar count and L2-normalising cancels it,
$\mathrm{normalize}(sv/sc) = \mathrm{normalize}(sv)$. The count therefore never
affects the ranking \emph{among the buckets we keep}, and releasing its magnitude is
strictly wasteful. We release \textbf{only the summed vector} (one composition):
identical retrieval to the last decimal at \textbf{${\sim}1.5\times$ tighter $\eps$}
(\secref{sec:accounting-results}). We call this the \emph{vector-only} release.

\paragraph{What the count channel was silently doing: occupancy.} Normalisation is
not innocent for a bucket nobody filled. If bucket $k$ has no contributors then
$S[k]$ is \emph{pure Skellam noise}, and line~\ref{alg:normalize} of
Algorithm~\ref{alg:main} projects it onto the unit sphere, manufacturing a random
unit vector that competes for top-$k$ slots against genuine centroids. Cosine
ranking cannot tell the two apart, so a release that keeps empty buckets can be
flooded with false positives. \textbf{Count magnitude cancels; occupancy does not.}
Three facts make this precise (all measured in \secref{sec:occupancy}):

\begin{enumerate}
  \item \textbf{It does not arise at the operating points.} With 10{,}957 notes over
    500 users, \textbf{no bucket is empty for $K \leq 128$ on any seed}, and
    $0.23 \pm 0.19\%$ at $K = 256$ (at most one bucket of 256). Every retrieval
    number in this paper is reported at $K \leq 256$, and the recommended point is
    $K = 32$. The noisy-normalisation failure mode is therefore \textbf{absent from
    the reported utility}, not tuned away.

  \item \textbf{Where it does arise, occupancy is expensive to release.} Under
    \textbf{user-level} DP a count channel is \emph{not} the cheap sensitivity-1
    object it would be under note-level DP: deleting a user erases \emph{all} of its
    entries at once. Even a \textbf{binary user-indicator} channel (the cheapest
    sensible variant, since a user contributes $0/1$ per bucket) has L2 sensitivity
    $\sqrt{b_u}$ ($\approx 5$--$8$ here, and its DP-selected public bound lands at
    $9.7$--$12.4$), \textbf{not 1}. The indicator channel is nonetheless the right
    one: at a full second composition ($\sigma_c = \sigma_v$, $\eps\ 9.31 \to 13.95$)
    it detects empty-vs-occupied at AUC $0.87 / 0.76 / 0.70$ for
    $K = 512 / 1024 / 2048$, against $0.82 / 0.68 / 0.63$ for raw counts. Made cheap
    ($\sigma_c = 2$, $\eps = 9.81$) it falls to $0.72 / 0.59 / 0.55$. Thresholding
    the released vector's own norm $\norm{S[k]}$ against the analytic noise floor
    $\sigma C \sqrt{d}$ is \textbf{free} (post-processing) but is at \textbf{chance}:
    AUC $0.52 / 0.48 / 0.49$.

  \item \textbf{The difficulty is intrinsic, not an implementation shortfall.} At the
    densities where buckets are near-empty, the noise that drives membership inference
    to chance in a one-contributor bucket (\secref{sec:proxy-blind}) is \emph{the same
    noise} that hides whether the bucket has a contributor at all. \textbf{Occupancy
    and membership are the same signal}; no mechanism hides the member and reveals the
    bucket.
\end{enumerate}

We therefore state the claim precisely: \textbf{vector-only dominates the two-channel
design at a fixed occupancy rule}, and at the recommended $K$ that rule is vacuous
because no bucket is empty. The sound response to a high-$K$ deployment is to
\emph{increase density} (coarsen $K$, which also maximises retention,
\secref{sec:usable}), not to bolt on a count channel that cannot pay for itself.

\begin{quote}
\textbf{No occupancy oracle in the reported numbers.} For the leakage measurement
(\secref{sec:proxy-blind}, \secref{sec:distilled}, \secref{sec:at-scale}) we release
the \textbf{vector-only} memory with \emph{no} occupancy suppression:
$\tilde\mu[k] = \mathrm{normalize}(S[k])$ for every bucket, so an empty bucket carries
normalized Skellam noise and nothing reads the clean counts. A non-private gate that
suppressed empty buckets using the true counts would move every tail-AUC by
$\leq 0.003$ (5-seed), inside the noise, because a member always occupies its own
bucket and a non-member in an empty bucket scores against noise either way. The only
clean-count quantity that survives is the \textbf{tail \emph{stratification}}
($\leq 3$ contributors), a property of our \emph{evaluation lens}, not of the release:
the adversary never sees it, and it selects which rows of results we report rather
than what the mechanism emits. The
occupancy \emph{rule} a dense high-$K$ deployment would need for retrieval is a
separate question, priced in \secref{sec:occupancy}.
\end{quote}

\subsection{Privacy accounting (exact Skellam-RDP)}\label{sec:accounting}

We account with the exact discrete guarantee of Agarwal, Kairouz \& Liu (NeurIPS
2021, Thm.~3.5)~\cite{agarwal2021skellam}, converting to $(\eps,\delta)$ through
R\'enyi DP~\cite{mironov2017rdp}:

% Broken across two lines: the one-line form overflows a two-column measure.
\begin{equation}\label{eq:skellam-rdp}
\begin{split}
  \eps_{\mathrm{RDP}}(\alpha) \;\leq\;
  &\frac{\alpha \Delta_2^2}{2\mu} \\[2pt]
  &{}+\; \min\!\left\{
    \frac{(2\alpha - 1)\Delta_2^2 + 6\Delta_1}{4\mu^2},\;
    \frac{3\Delta_1}{2\mu}
  \right\},
\end{split}
\end{equation}

with $\mu$ the per-coordinate released variance, $\Delta_2 = C s$, and
$\Delta_1 \leq \sqrt{K d} \cdot \Delta_2$ (the $\ell_1$ bound is taken over the
\emph{whole} $K d$-coordinate payload, because that is the object
line~\ref{alg:global-clip} clips; see Remark~\ref{rem:global-clip}). Since $B := C$
forces $\Delta_2 = C s = \texttt{range\_max} = 10^{6}$ exactly, the leading term
$\alpha \Delta_2^2 / 2\mu = \alpha / 2\sigma^2$ is independent of $C$ and $B$; the
correction term is not, but it is $O(10^{-4})$ here and never moves the reported
$\eps$. Composition over releases is additive in
RDP; we convert to $(\eps, \delta)$ by
$\eps = \min_\alpha \left[ \mathrm{RDP}(\alpha) + \ln(1/\delta)/(\alpha - 1) \right]$
($\delta = 10^{-5}$). This is implemented as \texttt{skellam\_rdp\_epsilon(...)} in
\texttt{qpriviot\_fl/privacy\_utils.py} and replaces the approximate single-shot
Gaussian labels used during exploration. \textbf{Every $\eps$ in this paper is the
rigorous Skellam-RDP value.} Table~\ref{tab:sigma-eps} gives a representative mapping
at the $K = 32$, $d = 32$ operating point.

$\sigma$}, re-labelling the $\eps$ axis leaves every ordering, retention percentage,
and AUC-drop unchanged.

\paragraph{On the choice of $\delta$.} The guarantee is at \textbf{user} granularity,
so the population size that $\delta$ must be compared against is the number of
\textbf{users} ($N = 500$), not the number of notes: the \texttt{s}-variant of
\secref{sec:at-scale} has 246{,}073 \emph{notes} contributed by those same 500 users.
The standard requirement is $\delta \ll 1/N$: here $1/N = 2 \times 10^{-3}$, so
$\delta = 10^{-5}$ sits \textbf{200$\times$ below} the threshold, comfortably inside
the safe regime. The requirement \emph{tightens} with the user count rather than
relaxing, so scale is the stress case, not the reassurance: a production fleet of
$N = 10^{5}$--$10^{6}$ \textbf{users} would need $\delta \ll 10^{-5}$. Our accountant
takes $\delta$ as a parameter, and the cost of retightening is mild: at fixed
$\sigma$, $\eps \approx 9.31 \to 10.08 / 10.85 / 11.45$ for
$\delta = 10^{-6} / 10^{-7} / 10^{-8}$ (and $\eps \approx 3.21 \to 3.50 / 3.76 / 4.01$).
Three orders of magnitude in $\delta$ cost \textbf{${\approx}23\%$ in $\eps$}, so the
mechanism carries to production-scale $\delta$ without re-tuning.

\subsection{The full mechanism}\label{sec:algorithm}

We consolidate \secref{sec:centroid}--\secref{sec:vector-only} into a single
end-to-end procedure (Algorithm~\ref{alg:main}). The \textbf{shared public parameters}
are the random-hyperplane LSH anchors $\{a_1, \dots, a_K\}$, the public-seed random
projection $P : \R^{D} \to \R^{d}$, the clip bound $C$, the quantiser bound $B$ and
step $s = \texttt{range\_max}/B$, the noise scale $\sigma$, a \textbf{survival floor}
$M_{\min}$ (\secref{sec:dropout}), and the clip-selection budget $\eps_c$
(\secref{sec:clip}; the clip bound $C$ and the quantiser bound $B := C$ are derived
once, publicly, from it). The target per-coordinate \emph{aggregate} Skellam variance
is $\mu = (\sigma C s)^2$; under SecAgg each client injects a $1/M_{\min}$ share, so
the masked integer sum realises at least $\mu$ with \textbf{no trusted curator} and
\textbf{no summand in the clear}. Only the \textbf{sum-vector channel} is released
(\secref{sec:vector-only}): dividing by the count and L2-normalising cancels the count.

\begin{algorithm*}[t]
\caption{Private Federated Memory Aggregation (SecAgg $+$ Skellam, vector-only
release). Public/shared parameters are as listed in the text above.}
\label{alg:main}
\footnotesize
\begin{algorithmic}[1]
  \Statex \textbf{\textsc{Server, once}} \hfill \emph{(public parameters; \secref{sec:clip})}
  \State $C \gets \textsc{ExpMech}_{\eps_c}\big(\text{grid},\,
         u(c) = -|\#\{u : \norm{V_u}_2 \leq c\} - 0.95 N|\big)$
         \Comment{DP-selected clip}
  \State $B := C$; \; $s \gets \texttt{range\_max}/B$; \;
         $\mu \gets (\sigma C s)^2$
         \Comment{$|\text{coord}| \leq \norm{V_u}_2 \leq C$}

  \Statex
  \Statex \textbf{\textsc{Client} $u$} \hfill \emph{(local; note text never leaves the device)}
  \For{each note $i$ of user $u$}
    \State $e_i \gets \mathrm{normalize}\big(P(\mathrm{Encoder}(\text{note}_i))\big)$
           \Comment{$384\text{-d} \to d$, L2-unit}
    \State $b(i) \gets \arg\max_k \langle e_i, a_k \rangle$
           \Comment{LSH bucket}
  \EndFor
  \State $v_u[k] \gets \sum_{i : b(i) = k} e_i$ \; for $k = 1 \dots K$
         \Comment{per-bucket sum-vector}
  \State $V_u \gets [\,v_u[1]; \dots; v_u[K]\,] \in \R^{K d}$
         \Comment{the user's \textsc{full} payload}
  \State $V_u \gets V_u \cdot \min\!\big(1,\, C / \norm{V_u}_2\big)$
         \label{alg:global-clip}
         \Comment{\textbf{global} clip $\Rightarrow \Delta_2 = C s$ (Rem.~\ref{rem:global-clip})}
  \For{each bucket $k = 1 \dots K$}
    \State $z_u[k] \gets \mathrm{round}\big(v_u[k] \cdot s\big) \in \Z^{d}$
           \Comment{quantise; $B := C$ never clips}
    \State $\tilde n_u[k] \gets \mathrm{Skellam}(\mu / M_{\min})$
           \label{alg:noise}
           \Comment{noise share, sized to survivors}
    \State $\tilde z_u[k] \gets z_u[k] + \tilde n_u[k]$
           \Comment{DP noise, in the integer domain}
    \State $m_u[k] \gets \tilde z_u[k] + \mathrm{mask}_u[k]$, \;
           $\textstyle\sum_u \mathrm{mask}_u[k] = 0$
           \Comment{SecAgg zero-sum mask}
  \EndFor
  \State \textbf{submit} $\{m_u[k]\}_{k=1}^{K}$ to the server

  \Statex
  \Statex \textbf{\textsc{Server}} \hfill \emph{(honest-but-curious; sees only masked sums)}
  \State \textbf{if} fewer than $M_{\min}$ clients survive \textbf{then abort}
  \For{each bucket $k = 1 \dots K$}
    \State $S[k] \gets \sum_{u \,\mathrm{alive}} m_u[k]
           = \sum_u z_u[k] + \mathrm{Skellam}\big(\tfrac{M}{M_{\min}}\mu\big)$
           \Comment{masks cancel}
    \State $\tilde\mu[k] \gets \mathrm{normalize}\big(S[k] / s\big)$
           \label{alg:normalize}
           \Comment{\textbf{every} bucket; no occupancy oracle (\secref{sec:vector-only})}
  \EndFor
  \State \textbf{release} the private centroid memory $\{\tilde\mu[k]\}_{k=1}^{K}$

  \Statex
  \Statex \textbf{\textsc{Retrieval}} \hfill \emph{(any downstream agent, query $q$)}
  \State \textbf{return} top-$k$ buckets by $\cos\big(\mathrm{normalize}(P(\mathrm{Encoder}(q))),\,
         \tilde\mu[k]\big)$ over $\{k : \tilde\mu[k] \neq 0\}$

  \Statex
  \Statex \textbf{\textsc{Accounting}} \hfill \emph{(\secref{sec:accounting}, exact Skellam-RDP)}
  \State $\Delta_2 \gets C s$; \; $\Delta_1 \gets \sqrt{K d}\,\Delta_2$
         \Comment{over the full $Kd$ payload; valid \emph{because} line~\ref{alg:global-clip} clips globally}
  \State $\eps_{\mathrm{RDP}}(\alpha) = \frac{\alpha \Delta_2^2}{2\mu}
         + \min\!\big\{\frac{(2\alpha - 1)\Delta_2^2 + 6\Delta_1}{4\mu^2},
                       \frac{3\Delta_1}{2\mu}\big\}
         + \frac{\alpha \eps_c^2}{2}$
         \Comment{last term: DP clip selection}
  \State $\eps \gets \min_\alpha \big[\eps_{\mathrm{RDP}}(\alpha) + \ln(1/\delta)/(\alpha - 1)\big]$
         \Comment{1 release $\Rightarrow {\sim}1.5\times$ tighter $\eps$}
\end{algorithmic}
\end{algorithm*}

\paragraph{Why each step matters.} Lines 3--5 place a note in the \emph{shared}
coordinate frame so different users' notes land in comparable buckets; both $P$ and the
anchors come from a public seed, so this step is data-independent and free
(\secref{sec:centroid}, \secref{sec:crossover}). Lines 6--\ref{alg:global-clip} are the
DP sensitivity: the clip is applied \textbf{once, to the concatenated payload}, because
a user who touches $b_u$ buckets would otherwise contribute $C$ to each and the true
sensitivity would be $\sqrt{b_u}\,C$ (Remark~\ref{rem:global-clip}). Lines 1--2 fix the
two public bounds before any user data is touched in the clear: $C$ by the exponential
mechanism (cost $\eps_c$, 0.2\% of the budget) and $B := C$ for free. The quantise/noise
lines move to the integer domain and add the discrete noise \emph{there}, which is what
makes it survive modular SecAgg. The mask line hides the contribution, and the server's
sum shows the masks cancel so the server learns only the sum. That sum is the crux:
because the sum of independent Skellams is Skellam, the per-client $\mu/M_{\min}$ shares
\textbf{compose to at least the central target $\mu$}, so the distributed release
\emph{equals} (or, on good turnout, exceeds) the intended central mechanism, a
property a continuous-Gaussian datastore lacks under modular arithmetic. Line
\ref{alg:normalize} releases \textbf{every} bucket, including empty ones: an empty bucket
therefore emits normalized Skellam noise rather than being suppressed. That is deliberate
and it is the reason the reported $\eps$ is honest. \emph{Any} occupancy gate that consults
the true counts is a non-private read of the corpus and an \textbf{unaccounted release},
precisely the error \secref{sec:clip} and \secref{sec:crossover} diagnose elsewhere. We
therefore pay its cost in utility instead of hiding it in the mechanism: every retrieval
number in this paper is measured with \emph{no} gate (\texttt{--gate none}), which at
$K \leq 256$ changes nothing (no bucket is empty at $K \leq 128$, and at $K = 256$ at most
one of 256 is, too few to alter a top-5 ranking: \texttt{--gate oracle} reproduces the
$K = 256$ column exactly) and at $K \geq 512$ costs the one or two
points of retention visible in Table~\ref{tab:frontier}. \secref{sec:occupancy} prices what
a \emph{private} gate would cost, and shows it cannot pay for itself. The implementation is
\texttt{apply\_distributed\_skellam\_noise} / \texttt{skellam\_noise} /
\texttt{generate\_zero\_sum\_masks} / \texttt{quantize} in
\texttt{qpriviot\_fl/privacy\_utils.py}, and the accounting is
\texttt{skellam\_rdp\_epsilon(...)}.

\subsection{Client dropout: the noise floor must be sized to survivors, not to
$N$}\label{sec:dropout}

Line~\ref{alg:noise} injects a $1/M_{\min}$ share rather than the naive $1/N$, and the
difference is not cosmetic. SecAgg deployments lose clients mid-protocol. If each of
$N$ clients injects $\mathrm{Skellam}(\mu/N)$ and only $M < N$ survive to
reconstruction, the server recovers aggregate variance
$\mu_{\text{actual}} = (M/N)\,\mu$, an \textbf{effective noise multiplier}
$\sigma_{\text{eff}} = \sigma\sqrt{M/N}$. The guarantee then degrades silently, and
worst exactly when participation is worst (Table~\ref{tab:dropout}).

  \centering

  each of $N$ clients injects a naive $\mu/N$ noise share but only $M$ survive.}

    \toprule
    survivors $M/N$ & 1.00 & 0.90 & 0.70 & 0.50 & 0.25 \\

    \bottomrule
  \end{tabular}
\end{table*}

Two sound remedies, either of which restores a valid guarantee:

\begin{itemize}
  \item \textbf{Calibrate to a survival floor $M_{\min}$} (Algorithm~\ref{alg:main},
    line~\ref{alg:noise}). Each client injects $\mathrm{Skellam}(\mu / M_{\min})$, so any
    turnout $M \geq M_{\min}$ realises variance $(M/M_{\min})\,\mu \geq \mu$: the
    guarantee \textbf{can only improve}, never degrade, and the server \textbf{aborts}
    rather than releasing if $M < M_{\min}$. The price is over-noising on good turnout.
    With $M_{\min} = N/2$ calibrated to $\eps \approx 9.31$ \emph{at the floor}, a
    full-turnout round realises $\sigma = 0.856$ and $\eps \approx 6.31$: utility is
    paid for at the floor, privacy is banked at the ceiling.

  \item \textbf{Fault-tolerant distributed noise generation.} Secret-share each client's
    noise seed exactly as SecAgg already secret-shares its mask
    seeds~\cite{bonawitz2017secagg}, so surviving clients reconstruct the dropped
    clients' noise shares and the aggregate variance is exactly $\mu$ for any $M$. This
    removes the utility penalty at the cost of another reconstruction round.
\end{itemize}

\textbf{Our experiments assume full participation} ($M = N = 500$, i.e.\
$M_{\min} = N$), with no straggler model. Dropout robustness is therefore something
this paper \emph{specifies} but does not \emph{measure}; we record it as a limitation
(\secref{sec:discussion}), not a claim.

\subsection{Repeated release: memory is re-aggregated, so the budget must
compose}\label{sec:multiround}

A model is trained once; a \textbf{memory} is not. Users write notes continuously, and
a deployed pool is re-aggregated on some cadence, which means the release of
\secref{sec:algorithm} happens $T$ times, not once, and \textbf{the guarantee that
matters is the composed one}. This is the assumption most easily left implicit, and
leaving it implicit is not benign: RDP composes \emph{additively}, so re-releasing at
the single-shot $\sigma = 0.606$ costs the budgets in the last column of
Table~\ref{tab:multiround}: $\eps \approx 93$ for a month of daily rounds, $\eps
\approx 153$ for a year of weekly ones. A mechanism advertised at $\eps \approx 9.3$
and re-run nightly is not an $\eps \approx 9.3$ mechanism.

The remedy is not to release once and hope. Because the composed RDP is linear in $T$
while the per-release RDP falls as $1/\sigma^{2}$, the noise scale needed to hold a
\textbf{fixed total budget} grows only as $\sqrt{T}$, so a cadence can simply be
\emph{bought} up front: pick the $T$ the deployment needs, solve for $\sigma$, and pay
for it once in utility. Table~\ref{tab:multiround} prices that trade at the recommended
$K = 32$, reading retention off runs actually executed at each $\sigma$ rather than
extrapolating.

  \centering

The headline is that the mechanism \textbf{survives a realistic cadence}: a pool
re-aggregated \textbf{monthly for a full year} (twelve releases, each incorporating
every note written since the last) costs \textbf{81\% retention at the same
$\eps \approx 9.3$} we report throughout, against 95\% for the single shot. Even a
month of \emph{daily} re-aggregation holds 73\%. What a deployment may \textbf{not} do
is re-release at the single-shot $\sigma$ and continue to quote the single-shot $\eps$.

Two properties make this cheaper than it first looks. The \textbf{public parameters do
not recompose}: the projection and anchors are public-seed (zero $\eps$ at any $T$), and
the clip bound $C$ is a \emph{public} bound over the payload norm, so it is selected once
and reused: we charge $\eps_c$ a single time, not $T$ times, and re-selecting it per
round would be an avoidable waste. And the guarantee is \textbf{user-level and
unbounded-DP}, so a user who writes no notes between rounds contributes an all-zero
payload and their privacy is not re-spent by the calendar; it is the \emph{release} that
composes, not the user. Sizing $\sigma$ to the planned horizon and aborting past it is
the sound discipline, exactly as $M_{\min}$ is for turnout (\secref{sec:dropout}).

\section{Experimental Setup}\label{sec:setup}
%%=====================================================================%%

\paragraph{Datasets / payloads.}
\begin{itemize}
  \item \textbf{LongMemEval (oracle)}~\cite{wu2024longmemeval}: real long-horizon
    conversational memory. Users $=$ question haystacks, notes $=$ dialogue turns,
    queries $=$ questions, ground truth $=$ evidence turns. The loader yields
    \textbf{500 users, 10{,}957 note embeddings, 479 queries with evidence}.
  \item \textbf{LongMemEval (\texttt{s})}~\cite{wu2024longmemeval}: the full-haystack
    variant, same 500 users but \textbf{246{,}073 note embeddings} (${\sim}96\%$
    distractors), ${\sim}22\times$ the oracle corpus, used for the at-scale generality
    check (\secref{sec:at-scale}).
  \item \textbf{LLM-distilled notes} (A-MEM/Mem0-style): dialogue turns distilled into
    memory notes by a local LLM (Ollama \texttt{qwen2.5:7b}). \textbf{500 users
    $\to$ 6{,}116 distilled notes}; a 100-user pilot $\to$ 1{,}715 notes. This is the
    realistic agent-memory payload, and the memory store for the live-agent attacks of
    \secref{sec:live-agent}.
  \item \textbf{Synthetic / real-embedding controls}: 20-Newsgroups with
    TF-IDF$\to$SVD and with real \texttt{all-MiniLM-L6-v2} embeddings, for controlled
    $N$/$K$/$d$ sweeps and a clean topic-accuracy metric.
\end{itemize}

\paragraph{Embeddings.} \texttt{all-MiniLM-L6-v2} (384-d)~\cite{reimers2019sbert},
reduced to the working dimension $d$ by a \textbf{public-seed Gaussian random
projection} (data-independent; \secref{sec:centroid}). Buckets are $K$
random-hyperplane anchors from the same public seed. For the \secref{sec:crossover}
ablation only, we additionally run two alternatives: \texttt{data-PCA} (PCA fit on the
users' notes, the unaccounted release) and \texttt{publicPCA} (PCA fit on a disjoint
public corpus: 20-Newsgroups for the LongMemEval runs, LongMemEval for the 20NG runs).
At $d = 384$ the projection is the identity, which is the ablation's control. Selected
by \texttt{--proj \{randproj,pca,publicpca\}}.

\paragraph{Mechanism.} Faithful crypto path (\texttt{privacy\_utils} quantize $\to$
Skellam $\to$ SecAgg-sum $\to$ dequantize), $\texttt{range\_max} = 10^{6}$. Vector-only
release unless stated. The clip bound $C$ is DP-selected once per run with the
exponential mechanism at $\eps_c = 0.1$ (\secref{sec:clip}, \texttt{--clip-eps}), and the
quantiser bound is $B := C$; both are public parameters of the released mechanism and
their cost is inside every $\eps$ we report.

\paragraph{Metrics.}
\begin{itemize}
  \item \emph{Utility}: evidence-recall@5 (LongMemEval), answer-recall@5 (distilled),
    topic-accuracy (controls); chance $\approx \mathrm{topk}/K$. We report
    \textbf{retention@$\eps$} $= \mathrm{utility}(\eps) / \mathrm{utility}(\text{clean})$.
  \item \emph{Leakage}: membership-inference ROC-AUC and \textbf{low-FPR TPR}
    (calibrated LiRA, \secref{sec:lira}) over all buckets and the \textbf{low-count tail}
    ($\leq 3$ contributors), a reconstruction-decode extraction rate
    (\secref{sec:lira}), and, against a live agent (\secref{sec:live-agent}), MEXTRA
    verbatim-recovery and MRMMIA-AUC. AUC $0.5$ / TPR $\approx$ FPR / chance-level decode
    $=$ no leakage.
\end{itemize}

\paragraph{Protocol.} \textbf{5 seeds (0--4)}, \textbf{final metric} (not peak),
mean $\pm$ std; the calibrated LiRA of \secref{sec:lira} uses 3 seeds $\times$ 48 shadow
releases and the live-agent attacks of \secref{sec:live-agent} run on
\texttt{qwen2.5:7b}. Members vs non-members are a same-distribution split of the note
pool (aggregated vs held-out), avoiding any train/test confound.

\paragraph{The frontier has an interior optimum, and it is where we already were.}
Three readings, all load-bearing.

\begin{enumerate}
  \item \textbf{DP defeats the calibrated attack at \emph{every} $K$.} LiRA AUC lands in
    $0.502$--$0.505$ and TPR@1\%FPR in $0.011$--$0.013$ (the false-positive floor)

    $0.998$. The privacy axis is therefore \textbf{flat}: it does not trade against $K$.
    Choosing $K$ is a pure utility decision, which is what makes the frontier readable.

    falls monotonically $95 \to 86 \to 72 \to 60 \to 41 \to 24 \to 13\%$ as $K$ grows

    bites. \textbf{$K = 32$ is the recommended point}: 95\% retention with the membership
    attack at the floor.

    that is a statement about the metric.} At $K = 32$ the \emph{membership} attack is
    fully defeated (TPR@1\%FPR $0.175 \to 0.011$) while \emph{reconstruction-decode} only
    halves ($0.771 \to 0.396$). We measured what \emph{chance} is for that metric by

    \textbf{$38\times$ above chance}: \textbf{DP does not defeat closed-set reconstruction
    at the recommended operating point}. \secref{sec:decode-floor} shows the fault is in the
    metric, not the release.
\end{enumerate}

\noindent\textbf{Summary of the frontier}: \emph{on the membership axis, the one the threat
model of \secref{sec:threat} is about, privacy is free across the whole sweep, so pick $K$
for the retrieval fidelity you need and pay the retention it costs.} $K = 32$ is our
recommendation, at 95\%.

\paragraph{Decode and retrieval are the same quantity.} Read the last two columns of
Table~\ref{tab:decode-floor} together: decode falls $0.396 \to 0.070 \to 0.001$ exactly as
retention falls $95\% \to 72\% \to 13\%$. This is not a coincidence, it is a tautology. A
centroid is useful for retrieval \emph{precisely when} it points at the notes in its own
bucket; ``the nearest note to $\tilde\mu[k]$ lies in bucket $k$'' is a restatement of ``the
pool retrieves.'' \textbf{One cannot drive closed-set decode to chance without destroying the
pool}, and $K = 2048$ (the only row that reaches the floor) is exactly the row whose
retention (13\%) makes it worthless. This is the same structure as the occupancy result of
\secref{sec:occupancy} (\emph{occupancy and membership are the same signal}), and it has the
same moral: a quantity that is inseparable from utility cannot be independently suppressed.

\paragraph{And a closed-set hit discloses nothing the adversary did not already have.} Recall
that we run the decode in its \textbf{strongest closed-set form}: the adversary is \emph{handed
the true candidate note set} and need only pick the right element (\secref{sec:live-agent}).
Such an adversary already possesses the notes. What a ``hit'' certifies is only that a note
they already hold falls in bucket $k$, and $\mathrm{bucket}(x) = \arg\max_k \langle x, a_k
\rangle$ is computable by \textbf{anyone}, from the \textbf{public} anchors, \emph{with no
access to the released pool at all} (\secref{sec:centroid}). The closed-set decode therefore
measures a quantity that is (i) identical to utility and (ii) available for free without the
release. It is an \textbf{upper bound} on inversion, and upper bounds are informative in one
direction only: the low values at $K \geq 1024$ \emph{do} certify that nothing is recoverable
there, while the high value at $K = 32$ certifies \textbf{nothing at all}.

\paragraph{What this leaves open.} The adversary a vector-only release must answer to is
\textbf{open-set embedding inversion}: recovering a note's \emph{text} from a released
centroid without being handed the candidates (a \texttt{vec2text}-style decoder). \textbf{We
do not run that attack}, and therefore do \textbf{not} claim that our release defeats
reconstruction. Our claim is narrower: \emph{membership inference (the threat this mechanism
is designed against, and the one the published attacks mount~\cite{chen2026mrmmia}) is driven
to the false-positive floor at every fidelity, while the closed-set extraction bound is
uninformative at usable $K$ for reasons that have nothing to do with the privacy of the
release.} Establishing open-set inversion resistance is the most important gap in this paper
(\secref{sec:discussion}).

\subsection{Calibrated attack: LiRA membership inference and
extraction}\label{sec:lira}

The similarity scores in \secref{sec:crossover}--\secref{sec:distilled} embody the
\emph{measurement principle} of MEXTRA/MRMMIA but are a weak, uncalibrated proxy. We now run
the \textbf{modern MIA standard} against the released pool: an \textbf{offline LiRA} that, for
each candidate note, estimates its membership-score distribution when it is \emph{aggregated
into} vs \emph{held out of} the pool from many \textbf{shadow releases} (cheap here: our
aggregation is numpy, not model training) and tests with the per-target likelihood ratio. We
report \textbf{ROC-AUC and the low-FPR TPR} (the operationally meaningful metric that AUC-only
proxies hide), plus a \textbf{reconstruction-decode extraction} attack (MEXTRA analog): decode
each released centroid to its nearest note and score a hit when the top-1 decoded note is a
true in-bucket member. Fits use a shadow split disjoint from the evaluation shadows (no
train-on-test bias).

This LiRA is scored \textbf{per candidate note over all buckets}, not only the sparse tail:
the TPR@1\%FPR of $0.945$ above is the all-bucket figure. It therefore already covers the
\emph{dense}-bucket case in which a single distinctive note pulls a centroid otherwise averaged
over dozens of predictable ``bystander'' contributors: the likelihood ratio is computed
against shadow releases with and without that exact note, so a unique contribution buried among
benign ones is precisely what the test is powered to detect. Sparse-tail stratification
(\secref{sec:proxy-blind}) reports where leakage \emph{concentrates}; it does not bound where
we \emph{looked}.

On \textbf{real \texttt{all-MiniLM-L6-v2} embeddings} the calibrated attack corroborates
\secref{sec:crossover}'s negative result: under the data-independent projection clean
TPR@1\%FPR is nearly \textbf{flat} across dimension, $0.967 \to 0.979$ for $d = 32 \to 384$
(decode $0.895 \to 0.966$), where the data-PCA grid shows a steep
$0.908 \to 0.979$. Tiny-$d$ buys essentially no leakage reduction once the projection stops
pre-anonymising the corpus, and DP collapses every cell to chance at $\eps \approx 9.3$
regardless of $d$ (TPR@1\%FPR $0.011 / 0.010$). (We headline the low-FPR TPR because AUC
becomes an unstable estimator at the largest $\sigma$, where it can tick up to $\approx 0.59$
even as TPR@1\%FPR stays at the ${\approx}1\%$ floor; the attack is defeated operationally
regardless.) This \textbf{upgrades the endpoint from a proxy to a calibrated attack}, leaving
only the \emph{LLM-agent-prompting} form of MEXTRA/MRMMIA (a live agent querying a text
store, a different release model than our centroid pool) as the subject of
\secref{sec:live-agent}.

At the recommended operating point ($K = 32$, $d = 32$) the private pool keeps
\textbf{95\%} of clean evidence-recall at $\eps \approx 9.3$ and \textbf{85\%} at
$\eps \approx 3.2$, at \textbf{$2.6\times$} chance. Utility is set by \emph{effective
contributors per bucket}: coarse buckets pool more users, so DP is nearly free; fine
buckets starve, so noise bites.

\paragraph{What ``retention'' is measured against, and the cost it does \emph{not} include.}
Retention throughout this paper is $\mathrm{utility}(\eps) / \mathrm{utility}(\text{clean
pool})$: it isolates \textbf{the cost of the privacy mechanism}, holding the architecture
fixed. It is \emph{not} the cost of the architecture, and the two should not be conflated.
Bucketing into $K$ centroids is itself a lossy retriever: on the controls, where the harness
also computes an un-bucketed nearest-neighbour reference over the same notes, plain kNN scores
$0.43$--$0.65$ against the clean bucketed pool's $0.19$--$0.32$ ($N = 100$, $K = 32$,
$d = 32$--$384$). \textbf{Coarse bucketing costs roughly half the retrieval utility, and DP then
costs a further 5\%}: the ``95\%'' does not mean the private pool is 95\% as good as having the
notes.

That un-bucketed retriever is, however, \textbf{not an available baseline in this setting}: it
requires every note in the clear at query time, which is precisely the object we may not
release; it is the artifact MEXTRA consumes (\secref{sec:live-agent}). It is an upper bound,
not a competitor. In short: \emph{a releasable shared pool costs about
half of an unreleasable one, and making it differentially private on top of that costs 5\%.}
Whether the first half is worth paying is a product question about what a fleet-level routing
prior is worth (\secref{sec:intro}); the second is the question this paper answers.

The $d$-sweep at fixed $K = 128$ shows \textbf{no dimension penalty}: retention is
\textbf{72\% $\to$ 77\% $\to$ 73\%} for $d = 32 \to 64 \to 128$, flat within seed noise.
Under the data-dependent PCA this same sweep reads $78\% \to 67\% \to 55\%$, an apparent
dimension effect; \secref{sec:crossover} explains why.

\subsection{The dimension ``crossover'' is an artifact of the
projection}\label{sec:crossover}

Under a PCA projection \textbf{fit on the users' own notes}, the data shows a
\textbf{dimension/density crossover}: growing $d$ appears to \emph{simultaneously} raise
pre-DP leakage and lower DP utility-retention, making tiny-$d$ Pareto-preferred and,
apparently, a free lunch. The finding does not survive an honest projection, and the way
it fails is instructive.

A data-fit PCA is a data-dependent release: $P$ is handed to every client as a public
parameter while being a function of private data, so the $\eps$ of \secref{sec:accounting}
would cover only the second stage. We therefore run the entire $d$-sweep under three
projections: \texttt{data-PCA}, a public-seed Gaussian \texttt{randproj}, and
\texttt{publicPCA} (PCA fit on a disjoint public corpus). \textbf{Everything else is held
fixed}, including the DP clip bound of \secref{sec:clip}. At $d = 384$ the projection is
the \textbf{identity}, so all three arms must coincide: that is the control, and they do
(Tables~\ref{tab:abl-utility} and~\ref{tab:abl-leakage}).

Both halves of the crossover dissolve. On the \textbf{utility} axis, tiny-$d$ wins by
91\% under data-PCA ($0.308$ vs $0.161$ at the identity), and under either
data-independent projection that advantage \textbf{disappears into the seed noise}:
randproj reads $0.151 / 0.178 / 0.158 / 0.161$ and publicPCA $0.147 / 0.150 / 0.142 /

$\pm 0.02$--$0.03$. The claim is \textbf{not} that tiny-$d$ becomes the \emph{worst}
choice (no ordering among $d$ is statistically resolvable at 5 seeds under either honest
projection), but that \textbf{the effect vanishes}: what replaces the crossover is a flat
line, not a reversal. On the \textbf{leakage} axis, the gradient that motivated
the claim ($0.944 \to 0.989$) likewise flattens to $0.988 \to 0.989$: once the projection
stops concentrating the corpus's shared variance, small $d$ no longer compresses away what
makes a note unique. And post-DP, tail-AUC sits at \textbf{0.50--0.55 for every $d$ and
every projection}: DP pins the attack at chance regardless of dimension, so the pre-DP axis
was never the operative one.

The mechanism is now visible. PCA orders directions by variance \emph{in the users' data};
at small $d$ it keeps exactly the directions the corpus shares and discards the
idiosyncratic tail. That simultaneously flatters clean retrieval and destroys the
individuating signal an attacker needs, which is precisely the ``both axes at once''
effect. But it purchases both with the same illicit currency: information about the private
corpus, spent outside the accountant. A random projection, spending nothing, buys neither.

\paragraph{What survives.} Tiny-$d$ remains a reasonable engineering default, on grounds
that have nothing to do with a privacy/utility joint optimum: at $d = 32$ the payload is
\textbf{$12\times$ smaller} ($K \cdot d = 1{,}024$ vs $12{,}288$ coordinates) and post-DP
leakage is \textbf{statistically indistinguishable} from the identity's
(Table~\ref{tab:abl-leakage}: $0.499$ vs $0.541$ tail-AUC at $\eps \approx 9.3$, both at
chance). Its private utility ($0.151$) is nominally $15\%$ below the best honest cell
($0.178$ at $d = 64$), but as noted above that gap is inside the seed noise and we do not
read an ordering from it. The case for tiny-$d$ is therefore a \textbf{communication/compute}
one (an order-of-magnitude smaller payload for no measurable privacy or utility cost),
and not a privacy/utility free lunch.

\paragraph{What this implies beyond this paper.} Data-dependent preprocessing (PCA,
whitening, vocabulary selection, learned quantisers, clip bounds read off the data;
\secref{sec:clip}) is both an unaccounted release \emph{and} a confound that can
manufacture a dimension effect out of nothing. It is standard practice. An
identity-projection control, of the kind used above, costs one extra run and would catch it.

\subsection{The weak attack is blind exactly where you would deploy}\label{sec:proxy-blind}

The cosine-similarity score of \secref{sec:threat}, which ranks a candidate by
$\cos(x, \mu[\mathrm{bucket}(x)])$, is the measurement principle of the published
agent-memory attacks~\cite{wang2025mextra, chen2026mrmmia} and the natural first
evaluation to reach for. It is also \textbf{actively misleading}, and in the direction that
matters: it under-reports leakage precisely in the coarse-$K$ regime a deployment would
choose.

\paragraph{The proxy certifies a leaking pool as safe.} Compare the two attacks on the
\emph{identical clean release} (Fig.~\ref{fig:joint-frontier}b). At $K = 32$ the cosine proxy
reads \textbf{AUC 0.504}, chance to three decimals; on this evidence the pool leaks
nothing and there is no privacy problem to solve. The calibrated LiRA, on that same
release, reads \textbf{AUC 0.833, TPR@1\%FPR 0.175 ($17\times$ the floor), and reconstructs
77\% of centroids to a true in-bucket note} (Table~\ref{tab:frontier}, $K = 32$). The pool was never safe. The proxy simply
could not see it, because an uncalibrated cosine score compares a member's similarity
against a \emph{population} baseline, and at coarse $K$ the population baseline is high:
every candidate is close to a centroid that averages hundreds of notes. Only a
\emph{per-target} likelihood ratio, calibrated against shadow releases with and without
that exact note, separates ``close because the bucket is broad'' from ``close because I
am in it.''

\paragraph{And it manufactures a false story about \emph{where} leakage lives.} Because the
proxy's sensitivity grows with $K$ (Fig.~\ref{fig:joint-frontier}b: $0.504 \to
0.738$ as $K$ goes $32 \to 2048$) while the calibrated attack is already strong at $K = 32$
($0.833$), a proxy-only evaluation concludes that leakage is a \textbf{sparse, high-$K$,
low-count-tail phenomenon}, a corner case present only in a regime whose utility
retention (13--41\%) nobody would ship. That conclusion is wrong twice: it understates the
threat at the deployed operating point, and it invites the reader to dismiss the mechanism
as solving a problem that only exists where the system is useless anyway.
Table~\ref{tab:leakage} preserves the proxy's numbers for the contrast.

\paragraph{What the proxy \emph{does} establish, kept for the record.} On the sparse tail it
is able to see ($K \geq 512$, where $2$--$16\%$ of members sit in buckets with $\leq 3$
contributors), clean memory re-identifies tail members at \textbf{AUC $\approx 0.93$} and DP
drives that to $0.53$--$0.55$ at $\eps \approx 9.3$. We state its residual precisely rather
than rounding it to ``chance'': the $0.03$--$0.05$ gap above $0.5$ is statistically
resolvable ($4.4\sigma$ at $K = 2048$). The calibrated attack answers what that residual is
\emph{worth}: at the same operating point LiRA reads AUC $0.504$ with TPR@1\%FPR on the 1\%
floor. So the residual is an artifact of the proxy's weakness in \emph{both} directions:
it sees a signal that buys nothing at high $K$, and misses one that buys plenty at low $K$.
This is why \secref{sec:frontier} headlines the calibrated low-FPR TPR throughout.

\paragraph{This confound is not specific to us.} \secref{sec:crossover} shows a
data-dependent \emph{preprocessing} step fabricating a finding; this section shows an
under-powered \emph{attack} erasing one. Both are defaults (PCA is the obvious projection,
cosine-similarity is the obvious membership score), and both bias the conclusion toward
``the mechanism is fine.'' An evaluation that reports only an uncalibrated proxy has not
measured privacy; it has measured its own attack. The remedy is cheap: our LiRA needs no model
training (the aggregation is \texttt{numpy}), and 48 shadow releases run in
\SI{34}{\second} per operating point.

\subsection{Accounting results}\label{sec:accounting-results}

The total $\eps$ decomposes cleanly, and three of its four terms are zero or negligible
(Table~\ref{tab:eps-decomp}).

\begin{table*}[t]
  \centering
  \caption{$\eps$ decomposition at $\sigma = 0.6056$, $\delta = 10^{-5}$, $K = 32$,
  $d = 32$. The reported budget covers the \emph{whole} pipeline, not just its last stage.}
  \label{tab:eps-decomp}
  \begin{tabular}{@{}lrl@{}}
    \toprule
    Term & $\eps$ & Note \\
    \midrule
    Continuous-Gaussian RDP reference   & 9.2909          & reference point \\
    $+$ discretisation (Skellam)        & 9.2909          & surcharge $1.3 \times 10^{-11}$: free at $\texttt{range\_max} = 10^{6}$ \\
    $+$ projection (public seed)        & 9.2909          & data-independent $\Rightarrow +0.000$ \\
    $+$ DP clip-bound selection ($\eps_c = 0.1$) & \textbf{9.3109} & \textbf{$+0.020$ (0.2\%)} \\
    \bottomrule
  \end{tabular}
\end{table*}

\begin{itemize}
  \item \textbf{Discretisation is free.} At $\texttt{range\_max} = 10^{6}$ the discrete
    Skellam $\eps$ equals the Gaussian-RDP $\eps$ to nine decimals; the integer/SecAgg
    quantisation costs no privacy.
  \item \textbf{The projection is free.} The public-seed random projection is
    data-independent, so it adds zero $\eps$, unlike the PCA it replaces, whose cost was
    unbounded and unaccounted (\secref{sec:crossover}).
  \item \textbf{The clip bound is nearly free in $\eps$, and cheap in utility.}
    DP-selecting $C$ with the exponential mechanism at $\eps_c = 0.1$ costs \textbf{0.2\%}
    of the budget (\secref{sec:clip}), and $B := C$ costs nothing at all. The selection is
    conservative (it over-estimates $C$ by ${\sim}1.6\times$ and therefore over-noises),
    which is what turns $0.416$ into \textbf{0.406} at $K = 32$ and $0.117$ into $0.100$ at
    $K = 256$.
  \item \textbf{Vector-only dominates, at a fixed occupancy rule.} At matched $\sigma$ the
    vector-only release gives \textbf{identical recall to the last decimal} as the
    two-channel design, at $\eps\ 14.0 \to 9.3$, because the count \emph{magnitude} only ever
    cancelled under normalisation. One composition, ${\sim}1.5\times$ tighter $\eps$, same
    utility. The one thing the count channel did supply is \textbf{occupancy} (which
    buckets are non-empty), and that does not cancel. At the $K$ we recommend and report, no
    bucket is empty, so the rule is vacuous and the domination is unconditional; at high $K$
    an occupancy channel must be bought, and \secref{sec:occupancy} measures what it costs
    and how well it works.

  \item \textbf{Repeated release is the one term that is \emph{not} cheap, and the one a
    memory pool cannot avoid.} Every entry above prices a \emph{single} release. A deployed
    memory is re-aggregated as users write notes, and RDP composes additively, so $T$ naive
    re-releases at $\sigma = 0.606$ cost $\eps \approx 22 / 44 / 93 / 153$ for
    $T = 4 / 12 / 30 / 52$ (Table~\ref{tab:multiround}). This dwarfs every other term in this
    table by two orders of magnitude, and it is the term most easily left implicit. It is,
    however, \emph{payable}: the required $\sigma$ grows only as $\sqrt{T}$, so a cadence can
    be bought up front: \textbf{monthly re-aggregation for a year at 81\% retention, inside
    the same $\eps \approx 9.3$} (\secref{sec:multiround}). The public parameters do not
    recompose ($C$ is selected once; the projection and anchors are public-seed), so the
    $\eps_c$ above is charged once regardless of $T$.
\end{itemize}

\subsection{Robustness}\label{sec:robustness}

Every number above is a \textbf{5-seed mean with the final (not peak) metric}, reported with
its std. The \texttt{--proj} flag is validated by checking that \texttt{--proj pca} reproduces
the data-PCA grid \textbf{bit-identically} (utility, leakage and distilled paths, to
$10^{-9}$), so the projection is the only variable in the \secref{sec:crossover} ablation. The
DP-selected clip bound (\secref{sec:clip}) changes every arm identically.

\subsection{At-scale generality (LongMemEval \texttt{s}, 246k
notes)}\label{sec:at-scale}

We repeat the utility and leakage measurements on the \textbf{full \texttt{s} variant}: the
same 500 users but \textbf{246{,}073 notes} (${\sim}96\%$ distractors), ${\sim}22\times$ the
oracle corpus. Both axes behave exactly as the density argument of \secref{sec:discussion}
predicts.

\paragraph{Utility is free.} See Table~\ref{tab:at-scale-utility}. The 100--101\% cells are

\paragraph{How to read this.} It is tempting to read Table~\ref{tab:at-scale-leakage} as showing
that the leakage-drop is ``really'' a sparse-tail phenomenon, and that the dense regime is
therefore \emph{safe on both axes for free} because averaging over hundreds of contributors
already destroys the membership signal. \textbf{That reading is an artifact of the proxy}
(\secref{sec:proxy-blind}). What the table shows is that the \emph{proxy's tail statistic}
vanishes at density, not that the pool stops leaking. The
calibrated attack breaks dense, coarse-$K$ releases: at $K = 32$ on the oracle corpus, where each
bucket averages ${\sim}340$ contributors and the cosine proxy reads $0.504$, LiRA reads AUC
$\mathbf{0.833}$ with a $17\times$-above-floor TPR (\secref{sec:frontier}). Averaging does not
anonymise; it only defeats an adversary who scores against a population baseline.

The at-scale run therefore \textbf{confirms the utility half and bounds the proxy}, rather than
bounding the result: at this density DP costs \emph{nothing measurable} on retrieval (97--100\%
retention, Table~\ref{tab:at-scale-utility}), which is the finding worth carrying. The leakage half
of the table should be read as a statement about the instrument, not about the release; it is
one more reason we headline the calibrated attack throughout.

\subsection{The published attacks against a live agent (MEXTRA /
MRMMIA)}\label{sec:live-agent}

The attacks so far operate on the released embeddings. To close the loop on the \emph{published}
threat model (a live LLM agent that stores and serves memory as \textbf{text}), we build an
A-MEM/Mem0-style shared-memory agent (local \texttt{qwen2.5:7b}) and run both attacks
end-to-end. The agent retrieves the top-$k$ shared-memory notes for a query into its context and
answers; the adversary issues (a) a \textbf{MEXTRA}~\cite{wang2025mextra} extraction prompt that
asks the agent to reproduce its memory verbatim, and (b) a \textbf{MRMMIA}~\cite{chen2026mrmmia}
membership probe for a candidate note. We hold the distilled notes fixed and swap only the
shared-memory back-end (Table~\ref{tab:live-agent}).

On the raw-text agent both published attacks succeed decisively: every targeted member note is
reproduced verbatim and membership is inferred at AUC $0.98$. Against our release both collapse:
membership is at chance ($0.526 \pm 0.044$, straddling $0.5$ across seeds:
$0.528 / 0.471 / 0.578$).

The private-column MEXTRA figure is \textbf{0.017, not 0}, and the distinction matters. The
centroid pool contains no member text, so verbatim recovery is \emph{structurally} impossible:
the agent's context holds only public notes decoded from centroids. The 1.7\% is therefore the
\textbf{false-positive rate of the recovery detector}: a decoded public note that happens to
sit within the $0.9$ embedding-similarity threshold of a target member note. It measures our
measurement, not the release.

\begin{quote}
\textbf{A harness pitfall.} The membership probe must not draw its non-members from the set that
also serves as the adversary's public decode corpus. In \texttt{private} mode the agent's context
\emph{is} that corpus, so non-member candidates appear verbatim in the context while members never
can, and the attack scores \textbf{below} chance (MRMMIA-AUC $0.31$--$0.35$; an inverting adversary
would read $0.65$--$0.69$). Any AUC that lands reliably below $0.5$ is a design error, not a
privacy result. The corpus is therefore split three ways (members / non-members / public decode
targets, pairwise disjoint), which is what the table above reports.
\end{quote}

(This is a demonstration at modest scale, not a tuned attack sweep; a stronger prompt-injection
adversary against the raw baseline would only widen the gap, since our release exposes no text
either way.)

\paragraph{How to read this, and what it does \emph{not} establish.} MEXTRA is a
prompt-injection attack that induces an agent to echo its \textbf{raw-text} memory. Our release
stores no text, so the correct claim is not that we \emph{defeat} MEXTRA but that we
\textbf{structurally immunise} the agent against it: the attack's target object no longer exists.
Stating it otherwise would be a strawman, since any vector-only datastore inherits the same
immunity for free. This section's role is therefore to show what the \emph{status-quo} raw-text
agent leaks, and that the artifact those published attacks consume is gone, not to certify our
release.

The adversary a vector payload genuinely must answer to is \textbf{embedding inversion}:
recovering a note from the released centroid. \textbf{We do not run that attack.} The
reconstruction-decode of \secref{sec:lira} is its \emph{closed-set} relaxation (the adversary
is handed the true candidate note set and need only pick the right element), and while that
upper-bounds free-form inversion (e.g.\ \texttt{vec2text}-style decoders), \secref{sec:decode-floor}
shows the bound is \textbf{uninformative at every usable $K$}, because it is the same signal as
retrieval and is satisfied by publicly computable bucket structure. It is therefore evidence
\emph{against} the release only where it is low ($0.003$ at $K = 1024$), and evidence of nothing
at $K = 32$ ($0.396$ against a $0.010$ chance floor). \textbf{We consequently make no claim that
our mechanism defeats extraction}, and identify open-set inversion as the paper's chief open
problem (\secref{sec:discussion}). What we do claim, and measure, is membership resistance.

\subsection{Occupancy: what the count channel actually
buys}\label{sec:occupancy}

An empty bucket is the one place the count channel is not redundant: \texttt{normalize} turns a
pure-noise $S[k]$ into a unit vector that competes for top-$k$ slots against genuine centroids. We
measure (a) how often empty buckets occur, and (b) whether they can be detected \emph{privately}.
Real LongMemEval-oracle (10{,}957 notes, 500 users, $d = 32$), the paper's mechanism (randproj, DP
clip), $\sigma_v = 0.6056$ ($\eps \approx 9.3$); occupancy over 5 anchor seeds, detection on a
single release. Reproduce with \texttt{scripts/agentmem/\_occupancy\_channel.py}.

\paragraph{(a) At the operating points, there are none.} See
Table~\ref{tab:occupancy-rate}. Every retrieval number in this paper is reported at
$K \leq 256$, where at most \textbf{one bucket of 256} is ever empty; at the recommended
$K = 32$ there are none on any seed. The noisy-normalisation failure mode is \textbf{absent from
the reported utility} rather than suppressed by tuning.

channel that cannot pay for itself.

%%=====================================================================%%
\section{Discussion and Limitations}\label{sec:discussion}
%%=====================================================================%%

\paragraph{The endpoint is \emph{not} confined to the sparse tail.} It is tempting to frame
the $0.9 \to 0.5$ drop narrowly, as \emph{``DP protects the vulnerable tail a sum mechanism
most exposes,''} on the grounds that dense buckets are protected by averaging anyway. That
framing is an artifact of the uncalibrated cosine proxy, which reports chance ($0.504$) at
$K = 32$ on a release the calibrated attack breaks at AUC $0.833$ with $17\times$-above-floor
TPR and 77\% note reconstruction (\secref{sec:frontier}, \secref{sec:proxy-blind}). Averaging
over a coarse bucket does \emph{not} protect its members; it only defeats an attacker who
compares against a population baseline instead of a per-target one. \textbf{The clean pool
leaks at every fidelity we measured, and DP pins the calibrated attack at the false-positive
floor at every fidelity we measured}: the privacy axis is flat in $K$, and the operating point
is chosen on utility alone. The at-scale \texttt{s}-variant (\secref{sec:at-scale}) is a genuine
boundary on the \emph{proxy}'s tail statistic (with 246k notes the low-count tail all but
vanishes), but not on the result.

\paragraph{Attack strength.} We evaluate at three escalating strengths and the endpoint holds at
each: (i) an embedding-similarity proxy (\secref{sec:crossover}, \secref{sec:proxy-blind}), which
we now report chiefly as a \emph{cautionary} instrument rather than as evidence; (ii) a
\textbf{calibrated offline-LiRA} MIA reported at low-FPR TPR plus a reconstruction-decode
extraction attack (\secref{sec:lira}), which reveal the clean pool is \emph{far} more leaky than
the proxy showed (at the recommended $K = 32$, TPR@1\%FPR $0.175$ and 77\% reconstruction where
the proxy saw nothing at all), yet still fall to the false-positive floor under DP; and (iii) the
\textbf{published MEXTRA/MRMMIA attacks against a live agent} (\secref{sec:live-agent}), which
fully extract a raw-text memory (recovery $1.0$, AUC $0.98$) but are driven to their detector's noise
floor against the centroid release (recovery $0.017$, AUC $0.526$). We note that this demonstration runs
at $K = 256$ with 60 users and 883 distilled notes (a smaller and sparser configuration than the
$K = 32$ operating point of \secref{sec:frontier}, and one for which we report no utility), so it
should be read as evidence about the \emph{status-quo raw-text} agent, not as a second measurement of
our recommended release. The endpoint therefore \textbf{strengthens} as the attack gets stronger.
Limits of (iii): it is a modest-scale demonstration on one open model with untuned extraction
prompts; a stronger prompt-injection adversary would widen, not close, the gap, since our release
exposes no text regardless. A user-level (rather than note-level) live-agent attack is left to
future work.

\paragraph{The biggest gap in this paper: we do not test open-set inversion.} DP drives
\emph{membership} to the false-positive floor at every fidelity we measured. It does
\textbf{not} drive \emph{closed-set reconstruction-decode} to chance at any usable $K$: at the
recommended $K = 32$ decode is $0.396$ against a measured chance floor of $0.010$, i.e.\
$38\times$ above it (\secref{sec:decode-floor}). We do not claim extraction is defeated.

We do argue, and measure, that the closed-set decode is the \emph{wrong instrument}: it
falls in lock-step with retrieval retention across the whole sweep because a centroid that
retrieves \emph{must} point at its own bucket, and a closed-set ``hit'' certifies only that a
note the adversary already holds falls in a bucket that the \textbf{public} anchors let anyone
compute without the release. It is an upper bound on inversion, informative only when low. But
an upper bound that is uninformative is not a defence, so \textbf{the reconstruction question is
open}. Settling it requires an \textbf{open-set embedding-inversion attack}
(\texttt{vec2text}-style recovery of note text from a released centroid), which we do not run:
the single most important experiment left undone. A reader who needs reconstruction resistance
today, rather than membership resistance, should not treat this paper as having supplied it.

\paragraph{Scope: the pool is a routing prior, not a note exchange, and our benchmarks test
routing, not downstream question answering.} The release is $K$ centroid vectors and \textbf{no
text}, so a receiving agent cannot read another user's note out of it, and we make no such claim
(\secref{sec:intro}). Utility is accordingly measured as \emph{routing} fidelity (did the query
reach the bucket holding its evidence?) and \textbf{not} as end-to-end answer quality. That gap
does not close on the benchmark we have. On
LongMemEval, a local agent (\texttt{qwen2.5:7b}) answering the questions with the private pool in
its context does \textbf{no better than with no pool at all}, and even a \emph{leaky} raw-text
shared pool helps only marginally. The reason is structural, not a failure of the mechanism:
LongMemEval is a \textbf{personal-recall} benchmark (``what was the first issue \emph{I} had with
my car''), whose every answer lives in one user's own history, so a \emph{cross-user} pool has no
relevant knowledge to contribute and merely injects other users' notes. It is exactly the wrong
benchmark for a shared knowledge prior, and it is the only realistic agent-memory corpus with
ground-truth queries currently available to us. Demonstrating downstream benefit therefore requires
a benchmark in which knowledge genuinely \emph{transfers} across users (one agent's hard-won fix
answering another's question), which to our knowledge does not yet exist; constructing one, and a
text-bearing second tier to serve it under its own budget (\secref{sec:discussion}, ``Stationarity
and fidelity''), is the most important piece of future work this paper points to. What we validate
here is the \textbf{privacy--routing} trade: that a shared routing prior can be released under a
guarantee, and that the release defeats membership inference. What we do not validate is the
downstream value of routing, which our benchmark cannot measure.

\paragraph{Deployment gaps we specify but do not measure.} Four, stated plainly.
(i) \textbf{Client dropout:} our runs assume full participation. A naive $\mu/N$ noise share loses
the guarantee precisely when turnout falls (at 50\% survival the true budget is $\eps \approx 13.9$,
not the nominal $9.3$), so a deployment must use the $M_{\min}$-calibrated share or fault-tolerant
noise reconstruction of \secref{sec:dropout}. We specify both; we measure neither. (Repeated release,
the sibling of this gap, we now \emph{do} account for and measure: \secref{sec:multiround}.)
(ii) \textbf{Occupancy at high $K$:} the leakage tables release the vector-only pool with \emph{no}
occupancy suppression, so they contain no oracle; adding a count-reading gate would move every
tail-AUC by $\leq 0.003$ (\secref{sec:vector-only}). What a dense high-$K$ deployment needs for
\emph{retrieval} (a private occupancy gate to keep noise-only buckets out of top-$k$) is a real
cost we do not pay here (we report retrieval only at $K \leq 256$, where at most one bucket of
256 is ever empty and the gate is measurably vacuous), and
\secref{sec:occupancy} prices it: no rule is simultaneously free and accurate, because occupancy and
membership are the same signal. Near-empty buckets cannot be \emph{both} privately aggregated and
privately enumerated. This cost is easier to avoid than to pay:
\secref{sec:frontier} shows the frontier's optimum is at coarse $K$ anyway.
(iii) \textbf{$\delta$ at production scale:} $\delta = 10^{-5}$ is $200\times$ below $1/N$ at our
$N = 500$ \textbf{users}, but a $10^{5}$-user fleet must retighten it (\secref{sec:accounting}), at a
cost of $< 23\%$ $\eps$.
(iv) \textbf{Drift across a multi-round deployment:} \secref{sec:multiround} prices the \emph{budget}
of $T$ releases but holds the corpus fixed; it does not model a fleet whose topics move between
rounds, which would additionally require the periodic re-seeding of the (public, zero-cost) bucket
geometry discussed below. The composition result is therefore sound as an accounting statement and
untested as a longitudinal one.

\paragraph{On the choice of $\eps \approx 9.3$.} It is not a tight budget by the standards of the
DP literature, and we do not present it as one. Two things should be weighed against it. First, it is
an \textbf{end-to-end} budget: it covers the projection, the LSH anchors, the clip bound and the
quantiser bound, every one of which is public or DP-selected (\secref{sec:accounting-results}). The
smaller $\eps$ values commonly reported for pipelines of this shape typically account only for the
final noise addition and silently exclude a data-dependent preprocessing step of exactly the kind
\secref{sec:crossover} shows to be both leaky \emph{and} distorting, so the numbers are not
comparable in the direction a reader would assume. Second, the empirical endpoint is what the budget
is \emph{for}: at this $\eps$, every attack we can mount (including the calibrated LiRA, the
reconstruction decode, and both published attacks against a live agent) is driven to its floor.

\paragraph{What the accounted pipeline costs.} Closing the two unaccounted releases, the
data-fit projection (\secref{sec:centroid}) and the data-read clip bound (\secref{sec:clip}),
lowers every clean-utility number in \secref{sec:results} by roughly a quarter ($K = 32$
evidence-recall $0.577 \to 0.428$). In exchange, the $\eps$ of \secref{sec:accounting} covers the
whole pipeline; the clip selection costs 0.2\% of it and $B := C$ costs nothing; and both the
leakage-drop endpoint (\secref{sec:proxy-blind}) and the calibrated attack (\secref{sec:lira}) get
\emph{stronger}, because the data-PCA had been pre-anonymising the corpus for free. The data-PCA
grid is reported alongside, as the \secref{sec:crossover} ablation.

We have not tried \textbf{DP-PCA} (fitting the projection under its own privacy budget), which is
the only route we know of that would recover the variance concentration soundly, at the cost of a
larger $\eps$ and a second mechanism to account for. That is the natural next step, and
\secref{sec:crossover}'s ablation quantifies exactly how much utility is on the table
($0.151 \to 0.308$ in private topic-accuracy at $d = 32$, if it could be had for free, which it
cannot).

\paragraph{Stationarity and fidelity.} Two structural assumptions. The bucket geometry is fixed for an
aggregation epoch, so a fleet-wide topic shift can starve some buckets (noise dominates) and crowd
others (the global clip bites). Because both the anchors and, once the fix above is applied, the
projection derive from a public seed or public data, the geometry can be \textbf{re-initialised
periodically at zero privacy cost}, which is the natural remedy; we do not evaluate drift. Separately,
$K = 32$ is a coarse memory: retrieval is bucket-granular and the pool is 32 vectors. Finer semantic
resolution need not come from pushing $K$ into the regime where buckets starve (\secref{sec:usable}); a
two-tier pool (coarse, dense, high-retention buckets for routing, then a sub-pool consulted after
routing) is the natural architecture, but the second tier needs its own privacy budget and is not
free. We leave it to future work.

\paragraph{Non-novel components, explicitly.} The dimension dependence of DP is
classical~\cite{chen2022price, bassily2014erm}. The apparent \emph{coupled} manifestation across
leakage and utility in agent memory is induced by a data-dependent projection
(\secref{sec:crossover}); what we claim on this axis is that refutation and the control that
exposes it. The SecAgg $+$ Skellam path is prior
work~\cite{bonawitz2017secagg, agarwal2021skellam, kairouz2021ddgauss}, and the
LSH-bucketing-plus-DP skeleton overlaps the centralized \emph{DP Datastore
Generation}~\cite{abouelenein2026dpdatastore} (\secref{sec:related}); the novelty is the
federated/curator-free SecAgg+Skellam composition, the agent-memory payload, the joint frontier and
its measured attack-drop endpoint, and the two methodological refutations
(\secref{sec:crossover}, \secref{sec:proxy-blind}).

\paragraph{What we would most like to be checked.} Two claims carry the paper, and both are cheap to
falsify. (i) That the \textbf{cosine proxy is blind at coarse $K$} (\secref{sec:proxy-blind}): a
single LiRA run at the reader's own operating point settles it, in under a minute on CPU. (ii) That
the \textbf{data-dependent projection manufactures the dimension effect} (\secref{sec:crossover}): an
identity-projection control at $d = D$, which all projections must agree on, settles that. Both are
one extra run.

%%=====================================================================%%
\section{Conclusion}\label{sec:conclusion}
%%=====================================================================%%

A shared LLM-agent memory pool can be made \textbf{usable and provably resistant to membership
inference at the same operating point}, a claim that only means anything if both axes are measured
there, which is the discipline this paper is organised around. Aggregating per-user bucketed memory
embeddings under Secure Aggregation and the Skellam mechanism yields a curator-free central-DP
\textbf{routing prior}: $K$ centroid vectors, no text, queryable by any agent in the fleet. On the
joint frontier (\secref{sec:frontier}) the coarse-$K$ regime is usable and safe together: at
$K = 32$ the pool retains \textbf{95\% of clean evidence-recall at $\eps \approx 9.3$} while a
calibrated likelihood-ratio attack falls from \textbf{AUC 0.833 and a $17\times$-above-floor
true-positive rate to the 1\% false-positive floor}. The membership axis is \textbf{flat in $K$}: DP
defeats the calibrated attack at every fidelity we measured, so $K$ is chosen on utility alone. The
scope of that claim is deliberate: closed-set \emph{reconstruction} is \textbf{not} driven to chance
at any usable $K$, and we show why the metric cannot be (it is the same signal as retrieval,
\secref{sec:decode-floor}). Open-set inversion
remains untested and is the paper's chief gap. Every parameter of the release is public or
DP-accounted, so that $\eps$ is the whole cost: the discrete mechanism is privacy-free at our
quantiser resolution, the public-seed projection is privacy-free by construction, the clip bound costs
0.2\% of the budget, and a vector-only release gives identical retrieval at ${\sim}1.5\times$ tighter
$\eps$. Because a memory is re-aggregated rather than released once, we compose over the deployment: a
naive cadence destroys the guarantee ($\eps\ 9.3 \to 93$ for a month of daily rounds), but the cost is
only $\sqrt{T}$ in the noise scale, so a \textbf{monthly re-aggregation sustained for a year fits inside
the same $\eps \approx 9.3$ at 81\% retention} (\secref{sec:multiround}). The endpoint holds on the
payload a production agent actually stores: run directly on LLM-distilled notes, the calibrated attack
is defeated at the same operating point and the same budget (\secref{sec:distilled}).

We also report \textbf{two negative results that travel}, both of which a single control run would
have caught. The dimension/density
``crossover'' that makes tiny-$d$ look like a joint privacy/utility optimum is an artifact of fitting
the projection on user data, an unaccounted release that flatters the clean baseline and
pre-anonymises the corpus at once; an identity-projection control catches it
(\secref{sec:crossover}). And the uncalibrated cosine proxy that agent-memory work reaches for by
default is \textbf{blind at exactly the operating point one would deploy}: it reports chance
($0.504$) at $K = 32$ on a release the calibrated attack breaks at AUC $0.833$, and it thereby
manufactures the comfortable conclusion that leakage is a sparse-regime curiosity rather than a
property of the pool you would actually ship (\secref{sec:proxy-blind}). The common shape is worth
naming: \emph{a default choice (the obvious projection, the obvious attack) that biases the
evaluation toward ``the mechanism is fine.''} Across three escalating attack strengths the endpoint
instead \emph{strengthens}: the raw-text memory of a live agent is fully extractable (recovery $1.0$,
AUC $0.98$), while our release, which contains no note text at all, drives both published attacks to
their detector's noise floor.

\section{Reproducibility}\label{sec:repro}

Active code lives in \texttt{scripts/agentmem/} (see \texttt{scripts/README.md}); the pooled crypto is
\texttt{qpriviot\_fl/privacy\_utils.py}.

\begin{itemize}
  \item \textbf{Utility}: \texttt{\_longmemeval\_probe.py} (real),
    \texttt{\_agentmem\_probe.py} (controls),
    \texttt{\_longmemeval\_distilled\_utility.py} (distilled).
  \item \textbf{Leakage (proxy)}: \texttt{\_longmemeval\_leakage.py},
    \texttt{\_agentmem\_leakage.py}, \texttt{\_longmemeval\_distilled\_analysis.py}
    (raw-vs-distilled).
  \item \textbf{Leakage (calibrated, \secref{sec:lira})}: \texttt{\_agentmem\_lira.py}, which runs
    offline-LiRA MIA (AUC $+$ low-FPR TPR) and reconstruction-decode extraction via shadow releases.
  \item \textbf{Leakage (live agent, \secref{sec:live-agent})}: \texttt{\_agentmem\_llm\_attack.py},
    an A-MEM/Mem0-style shared-memory agent (local Ollama) under end-to-end MEXTRA extraction $+$
    MRMMIA membership prompts, contrasting a raw-text memory vs our centroid release. Takes
    \texttt{--proj}/\texttt{--clip-eps} like the rest; the note corpus is split three ways (members /
    non-members / public decode corpus, pairwise disjoint), without which the membership probe scores
    below chance (\secref{sec:live-agent}). Results in \texttt{experiment\_results/llm\_attack\_rp/}.
  \item \textbf{Joint frontier (\secref{sec:frontier}) and multi-round (\secref{sec:multiround})}:
    \texttt{scripts/shell/rerun\_joint.sh} fills the cells the headline grid omits (utility at
    $K \geq 512$, the cosine proxy at $K \leq 256$, and the \emph{calibrated} LiRA at
    $K \leq 256$) into \texttt{experiment\_results/joint\_rp/}, and prices the $T$-round
    schedule by injecting the solved $\sigma$ via \texttt{--fl\_sigma}.
    \texttt{\_joint\_frontier.py} regenerates Table~\ref{tab:frontier},
    Table~\ref{tab:multiround} and \texttt{figures/fig\_joint\_frontier.pdf} from those JSONs
    (\texttt{--latex} emits the table bodies). The LiRA-at-low-$K$ runs are the load-bearing
    ones: they are what shows the cosine proxy of \texttt{\_longmemeval\_leakage.py} to be at
    chance on a release the calibrated attack breaks (\secref{sec:proxy-blind}).

  \item \textbf{Accounting}: \texttt{\_skellam\_accounting.py} (Skellam-RDP $\eps$;
    discretisation-free check). Multi-round composition is the \texttt{releases=} argument of
    \texttt{skellam\_rdp\_epsilon(...)}, already present in \texttt{privacy\_utils.py}; the
    $\sigma$ column of Table~\ref{tab:multiround} is a bisection against it
    (\texttt{sigma\_for()} in \texttt{\_joint\_frontier.py}).
  \item \textbf{Distillation}: \texttt{\_longmemeval\_distill.py} turns LongMemEval turns into
    A-MEM/Mem0-style notes via a local Ollama model (\texttt{qwen2.5:7b}); it checkpoints
    incrementally.
  \item \textbf{Projection (\secref{sec:centroid}, \secref{sec:crossover})}: every script takes
    \texttt{--proj \{randproj,pca,publicpca\}}; \texttt{randproj} is the public-seed,
    data-independent default (\texttt{make\_projector} in \texttt{\_agentmem\_probe.py},
    \texttt{PUBLIC\_PROJ\_SEED}). \texttt{--proj pca} reproduces the data-dependent grid
    \textbf{bit-identically}, which is how the \secref{sec:crossover} ablation isolates the projection
    as the only variable.
  \item \textbf{Clip bound (\secref{sec:clip})}: every script takes \texttt{--clip-eps} (default
    \texttt{0.1}). \texttt{dp\_quantile\_clip} in \texttt{qpriviot\_fl/privacy\_utils.py} is the
    exponential mechanism over the public grid \texttt{PUBLIC\_CLIP\_GRID};
    \texttt{skellam\_rdp\_epsilon(..., clip\_eps=, clip\_releases=)} folds its cost into the reported
    $\eps$. \texttt{--clip-eps 0} selects the unaccounted empirical p95 instead.
  \item \textbf{Drivers $\to$ tables/figures}: \texttt{scripts/shell/rerun\_final.sh} runs the headline
    5-seed grid into \texttt{experiment\_results/rerun\_grid\_rp/*.json}, the at-scale
    \texttt{s}-variant into \texttt{rerun\_grid\_s\_rp/*.json}, and the two \secref{sec:crossover}
    ablation arms into \texttt{rerun\_grid\_abl\_pca/} and \texttt{rerun\_grid\_abl\_pp/} (identical to
    the headline except for \texttt{--proj}). \texttt{scripts/shell/rerun\_lira.sh} (with
    \texttt{--proj randproj --clip-eps 0.1}) runs the calibrated-attack grid (\secref{sec:lira}) into
    \texttt{experiment\_results/lira\_rp/*.json}. \texttt{rerun\_figures.py --grid rerun\_grid\_rp}
    regenerates \texttt{figures/fig\_*}. The data-PCA grids (\texttt{rerun\_grid},
    \texttt{rerun\_grid\_s}, \texttt{lira}) are retained to certify the bit-identical
    \texttt{--proj pca} check of \secref{sec:robustness}. Each script has an additive \texttt{--json}
    dump; the crypto path is byte-identical to the released \texttt{privacy\_utils}.
  \item \textbf{Occupancy channel (\secref{sec:occupancy})}: \texttt{\_occupancy\_channel.py}.
  \item \textbf{Occupancy gate (\secref{sec:algorithm})}: \texttt{\_longmemeval\_probe.py} takes
    \texttt{--gate \{none,oracle\}}, default \texttt{none}. \texttt{none} releases \emph{every}
    bucket, so an empty one carries normalized Skellam noise; this is the mechanism of
    Algorithm~\ref{alg:main} and it is what every retrieval number in this paper is measured under.
    \texttt{oracle} suppresses empty buckets using the clean counts, a non-private read of the
    corpus and therefore an unaccounted release. It reproduces the $K \leq 256$ columns exactly
    (verified: no bucket is empty at $K \leq 128$, and the at most one empty bucket of 256 at
    $K = 256$ never enters a top-5 ranking) and changes only the high-$K$ cells.
\end{itemize}

Run: \texttt{bash scripts/shell/rerun\_final.sh \&\& bash scripts/shell/rerun\_joint.sh \&\& python
scripts/agentmem/rerun\_figures.py --grid rerun\_grid\_rp} (and \texttt{bash
scripts/shell/rerun\_lira.sh} for \secref{sec:lira}; \secref{sec:live-agent} needs a local
\texttt{ollama serve} with \texttt{qwen2.5:7b}).

\end{appendices}
