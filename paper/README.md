## Building

```powershell
cd paper
.\build.ps1
```

That runs the full `pdflatex -> bibtex -> pdflatex -> pdflatex` cycle and prints a
report (errors / undefined refs / overfull boxes / bibtex warnings / bib entries).
It exits non-zero on failure and points at the offending line, so it is safe to
chain or run in CI. Flags:

| Flag | What it does |
|---|---|
| *(none)* | Full build. This is what you want. |
| `-Figures` | Regenerate `figures/fig_*.pdf` from `experiment_results/` first. Only needed if the experiment grid has been re-run. |
| `-Quick` | One `pdflatex` pass, no bibtex. Fast prose check; cross-refs and citations will be stale. Not for a final PDF. |
| `-Clean` | Delete build artifacts and the PDF, then exit. |

All four passes are required for a correct PDF: `pdflatex` emits the `.aux`,
`bibtex` builds the bibliography from it, and two more `pdflatex` runs settle the
citation numbers and the `\ref`s (figure / table / algorithm / **line** numbers).
Stopping early leaves `??` in the text.

MiKTeX is installed user-scope (`winget install MiKTeX.MiKTeX`) and is **not** on
the global PATH — `build.ps1` prepends it. Missing LaTeX packages are auto-installed
on first use (`initexmf --set-config-value=[MPM]AutoInstall=1`); without that the
build dies on a missing `cuted.sty` that `sn-jnl.cls` pulls in.

**Overleaf:** upload `paper/` plus `figures/`, set the compiler to pdfLaTeX and the
main document to `qpriviot-memory.tex`.

### Doing it by hand

```powershell
$env:PATH = "$env:LOCALAPPDATA\Programs\MiKTeX\miktex\bin\x64;$env:PATH"
pdflatex qpriviot-memory
bibtex   qpriviot-memory
pdflatex qpriviot-memory
pdflatex qpriviot-memory
```

Note: PowerShell 5.1's `>` redirection writes **UTF-16**, so `grep` cannot read a
captured build log — inspect it with `Select-String`. (Relatedly, do not redirect a
native exe's stderr with `*>` or `2>&1` in a script: PS 5.1 wraps each stderr line in
an ErrorRecord, and MiKTeX's harmless "you have not checked for updates" nag then
reads as a fatal error. `build.ps1` uses `Start-Process` to sidestep this.)

## Citation links (and a patch to Springer's `.bst`)

Every citation is clickable:

- **In-text** `[n]` markers jump to the bibliography entry (hyperref, via `sn-jnl.cls`).
- **In the bibliography**, each entry carries a clickable **DOI** or **arXiv** link,
  rendered by the `.bst` from the `doi` / `eprint` fields in `references.bib`.

The second half needed a fix. Stock `sn-mathphys-num.bst` calls `format.doi`,
`format.eprint` and `format.url` **only from `FUNCTION {article}`** — so every
`@inproceedings` entry silently dropped its identifier and rendered with no link at
all. Since most of the references are conference papers, most of the bibliography
was dead text. The `sn-mathphys-num.bst` in this directory carries a **local patch**
(clearly commented, at the tail of `FUNCTION {inproceedings}`) that mirrors
`article`'s link block. **If you re-copy the style from `bst/`, you lose the patch.**

Springer's production system re-typesets the bibliography from your `.bib`, so this
patch affects your preprint / submission PDF, not the final published record.

## Draft defects that were found and fixed during the port

These were real errors in `Draft_v2.ipynb`, not artifacts of the port:

1. **`Remark 1` appeared twice with conflicting numbers.** One version had
   `b_max = 54` @K=1024 and ε 9.31 → 69/159; the other had `b_max = 47` and
   ε 9.28 → 69/140. They also disagreed on whether the global clip is line 7 or 8
   of Algorithm 1. **Resolved against the harness**, not by picking a side: with
   the 5-seed random-projection grid, the busiest user touches `b_max = 21` buckets
   at K=32 and **54** at K=1024 (the "47" was the *seed-0* value, not the max over
   seeds — that is where the two versions diverged). Re-deriving the true ε under
   per-bucket clipping (noise sized to `C`, sensitivity `sqrt(b_max)*C`) gives
   **68.7** (K=32) and **158.6** (K=1024) against a nominal 9.30. So the first
   version's numbers were right and the second's line reference was right. The
   surviving Remark carries both, and the line number is now a `\ref` to a
   `\label` on the clip line, so it can never drift again.
2. **The figures contradicted the tables.** `rerun_figures.py` plotted the x-axis
   with the *exploration* budgets (1 / 3 / 8 / 16), which are the classic-Gaussian
   labels the runs were named after and are invalid for ε > 1, while every table
   and every sentence in the paper reports the rigorous Skellam-RDP ε
   (1.1 / 3.2 / 9.3 / 22.1). Fixed in the generator (`EPS_X`, `_eps_axis`) and all
   five figures regenerated, so the axes now match the claims.
3. **Refs [1], [3], [4]** (McMahan, Abadi, Mironov) were listed but never cited, so
   BibTeX would have silently dropped them. Now cited where they belong — FedAvg and
   DP-SGD in the related-work paragraph on federated DP, Mironov where RDP is
   introduced in §5.4. All 22 entries render.
4. **One reference had the wrong title.** `lin2026survey` was recorded as
   *"…: Attacks, Defenses and Evaluation"*. The arXiv ID is correct but the real
   subtitle is *"…: Attacks, Defenses, and Governance Across the Memory Lifecycle"*.
   Corrected.
5. **Three references had gone stale as "arXiv preprint".** They are published:
   `xu2024amem` (A-MEM) is NeurIPS 2025, `wu2024longmemeval` is ICLR 2025, and
   `chhikara2024mem0` (Mem0) is ECAI 2025 and now has a real publisher DOI
   (`10.3233/FAIA251160`). Venues and years updated; the bibtex *keys* keep their
   original year suffix so the `.tex` needed no edits.

   All 22 identifiers were verified against the live record (arXiv abstract page
   **and** the arXiv API, which errors on a nonexistent ID; DOIs against Crossref,
   DBLP and the ACL Anthology). The nine 2025–2026 arXiv IDs the draft claimed all
   resolve to the claimed papers. Two entries genuinely have **no** arXiv version
   (`bonawitz2017secagg`, `smith2011quantile`) despite being widely miscited as if
   they did — do not let anyone add one.
4. **There was no §5.1.** The draft jumped from unnumbered prose to §5.2. A §5.1
   ("Clipping, quantisation, and sensitivity") now closes the gap.
5. **No author block existed.** Single-author stub added from the repo's git identity.
